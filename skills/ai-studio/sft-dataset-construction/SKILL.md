# SFT 数据集构建（全流程编排）

定位：从种子数据到可训练数据集的完整闭环。不重复实现评估与增强——评估调 `sft-dataset-assessment`，增强调 `sft-dataset-augmentation`，本技能负责决策与编排。

## 何时用
- 用户给一批种子数据，要"做成可微调的数据集"
- 数据增强 + 质量评估 + 切分打包一条龙

## 编排流程

```
1. 数据评估（sft-dataset-assessment）→ 缺陷报告
2. 按 severity 设计增强方案表 → 用户确认
3. 执行增强（sft-dataset-augmentation）
4. 再评估 → 未达标迭代（通常 2-3 轮）
5. 合并 + 组级切分 + 最终质检 → 交付
```

## 决策框架（先回答，再动手）

1. **有没有原始文档？** 有=可做深层构造；只有 QA=只能种子变换
2. **事实零新增？** 垂域安全增强默认 safe；推断类 full 版需人工审核
3. **先画像再选策略**：类型分布、列表占比、复合多问数决定哪些增强有效
4. **增强 ≠ 越多越好**：宁缺毋滥，各阶段量不齐没关系
5. **方案先行**：评估→出方案表→用户确认→一次做完全范围。每阶段带耗时/token 估算

## 增强方案表模板

| 缺陷 | 阶段 | 方法 | 预计产出 | 事实新增 | 成本 |
|------|------|------|---------|---------|------|
| 类型失衡 how 40% | stage3 | 定向反向 + 配额 | +1500条 | 无 | 中 |
| 定义类缺失 | stage9 | 规则提取+人工审 | +80条 | 无 | 低 |
| 拒答不足 0.9% | stage7 | 领域内越界生成 | +50条 | 特殊 | 低 |

## 切分与合并

- **schema 统一**：Alpaca 扩展，单文件，无 dev 集
- **train 98% / test 2%**（用户定案），val 训练框架内部从 train 随机切
- **组级切分防泄露**：按 group_id 分层，同出处衍生样本同侧
- **增量合并不动 test**：新增条目用固定 group_id 前缀，全部落 train
- **合并前对账**：按 source 分层校验各层条数，不齐 = schema 丢字段

## 交付物

- 数据集文件（train/test，单文件 + split 字段）
- 质量评估报告（最终版）
- 各阶段产出统计 + 失败条目清单
- 来源分布 / 类型分布 / 长度分布统计表

## 用户偏好（实证）

- 失败条目不允许跳过，100% 补全
- 修复/扩展方案先出表待确认，不边跑边改
- 进展直接给表格（阶段/状态/成功/失败/产出）
- 质量优先数量："是多少就是多少"
- 交付：HTML 单文件发飞书，不打包
