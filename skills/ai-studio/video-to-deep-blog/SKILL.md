# Video → Deep Blog
## 视频字幕转专业深度长文

### 什么时候用
用户提供视频字幕文件（人工提取的 .txt/.srt/.md），要求写成一篇专业深度的博客/文章。

不依赖任何 YouTube API——字幕由用户人工提供。
适用于：纪录片、演讲、访谈、技术讲解、行业分析等信息量充足的视频内容（通常 > 20 分钟）。

---

## 核心原则

> 本技能遵循 ai-studio 体系共享规则（见 `../shared/RULES.md`）：
> 事实零演绎、专业优先、有推理链、有反方视角、可溯源。
> 以下是本技能特有的原则。

- **原片内容为主，扩充为辅**：原片事实 ≥ 60%，补充内容 ≤ 40%
- **三层明确区分**：原事实 / 背景知识 / 分析判断，读者能看出来哪层是哪层
- **不做字幕整理**：输出是文章，不是 transcript 分段版。要有主线、有叙事、有洞察

## 写作硬约束（一票否决）

以下任何一条不合格，就是垃圾，必须重写：

### 1. 段落成块，禁止碎片化
- 每段 **200-400 字**，围绕一个核心论点展开
- 段落结构：**论点 → 论据（事实/引语/数据）→ 分析**，三层完整
- **绝对禁止一句话一段**——那是微博不是文章
- 段与段之间有逻辑衔接，不是独立点的罗列

### 2. 提炼优先，禁止流水账
- 每章必须有 **一个核心论点**，所有素材都是为了支撑这个论点
- 不是按时间顺序把素材堆一遍，是从素材里提炼出观点，用素材证明观点
- 读者读完一章，应该能用一句话说清楚"这章说了什么"
- 如果章名就是一个时间段（如"1995年"），那就是流水账，不合格

### 3. 素材形状决定结构，不硬套模板
- 模板是参考起点，不是枷锁
- 必须根据素材的**内在逻辑**来组织结构，素材是什么形状，文章就是什么形状
- 如果模板的章节数、章节划分跟素材不匹配，改模板，不要硬塞素材
- 判断方法：删掉模板名称，能不能根据素材自然得出这个结构？能就是合格的

### 4. 专业深度，不是术语堆砌
- "专业"不是堆术语，是**有技术拆解、有行业背景、有逻辑推理**
- 第一次出现的技术术语必须有简短解释（一两句话说清是什么）
- 分析要深入一层：不仅说"发生了什么"，还要说"为什么会这样"、"这意味着什么"

### 5. 反方视角融入，不是补丁
- 反方视角/局限性/风险，要**融入对应章节**里自然呈现
- 不要单独切一个"【反方视角】"小段落放在最后，像补丁
- 分析一个观点时，自然带出"当然，也有人认为……"、"但这个判断的前提是……"

## 七步工作流

### 输入
- 字幕文件（.txt / .srt / Markdown 均可）
- 可选：视频标题、来源链接、视频时长、目标字数

### 输出
- **专业深度长文 Markdown**（4000-8000字）
- **HTML 页面**（调用 ai-content-imagery 的 generate_article.py）
- 可选附赠品：章节摘要、金句摘录、时间轴

---

## 七步工作流

### Step 1：字幕预处理
- 清洗：去除时间戳、行号、重复片段、广告/赞助口播
- 分段：按语义主题粗分（不是按时间戳分，是按话题转换分）
- 统计：总字数、主要话题、出现的人物

**产出：** 纯净文本 + 粗分段清单

### Step 2：素材盘点
从字幕中系统提取以下素材，列成清单：

| 素材类型 | 提取什么 |
|----------|----------|
| **核心人物** | 姓名、身份、角色、关键原话 |
| **关键事件** | 时间、地点、事件、结果 |
| **金句/原话** | 有冲击力的原话，附大致时间点 |
| **时间轴** | 关键节点的先后顺序 |
| **技术点** | 提到的技术概念、原理、方案 |
| **数据点** | 具体数字、比例、金额、规模 |
| **矛盾/冲突** | 观点对立、利益冲突、失败教训 |

**产出：** 素材清单（结构化）

### Step 3：主题判断
判断视频类型，决定写作框架：

| 类型 | 识别特征 | 典型例子 |
|------|----------|----------|
| **纪录片/传记型** | 有时间线、有人物故事、有起承转合 | 公司发展史、人物传记、技术史 |
| **技术讲解型** | 核心是讲一个技术/工具/方法的原理和用法 | 架构拆解、工具评测、教程 |
| **行业分析型** | 讲趋势、市场、商业模式、产业格局 | 市场报告、行业观察、趋势分析 |
| **演讲/访谈型** | 单个人讲观点，或对话形式 | TED、播客访谈、会议演讲 |
| **多源综合型** | 需要把多个视频/话题串成一个主题 | （用户提供多个字幕文件） |

**产出：** 类型标签 + 核心论点（一句话概括文章要说什么）

### Step 4：结构设计
按类型匹配标准结构，设计章节大纲。

**隐式确认节点：** 完成结构设计后，把「章节大纲 + 各章核心论点 + 素材映射」作为中间产出列出来（表格形式），
不主动停下来询问。用户如有意见会回复纠正；无反馈则继续 Step 5。
这样既保证流程连续，又给用户留了纠偏窗口——结构错了，重写成本极高，这里值得多花一分钟。

每个章节必须明确：
- 章节主题（一句话）
- 章节核心论点（这章要证明什么）
- 用哪些素材支撑
- 补充哪些背景知识
- 在全文叙事中的作用（起/承/转/合）

**产出：** 文章大纲（标题 + 各章节主题 + 核心论点 + 素材映射）

### Step 5：深度扩充写作
按大纲写全文。重点注意：

**扩充内容的三个来源（允许的）：**
1. **公开常识** ——比如"Java 发布于 1995 年"这种众所周知的事实
2. **行业共识** ——比如"RLHF 是目前主流的对齐方法"这种行业普遍认知
3. **逻辑推演** ——基于原片事实的合理推理和分析（必须标注是分析）

**禁止的：**
- 编造原片没有的具体事件、数字、人物原话
- 脑补人物心理活动
- 把猜测当事实

**标注规范：**
- 直接引语 → 加引号 + 标注"某某说"
- 背景知识 → 用"【背景知识】"前缀或单独成段
- 分析观点 → 用"笔者认为"或"从这个角度看"明确标示

### Step 6：润色打磨
- **叙事节奏**：张弛有度，故事段和分析段交替
- **过渡衔接**：章节之间、段落之间有自然过渡
- **开头结尾**：开头有钩子，结尾有升华
- **标题优化**：主标题有冲击力，副标题说明范围
- **通读检查**：事实准确性、逻辑连贯性、有没有演绎成分

### Step 7：HTML 生成与交付
- 调用 `ai-content-imagery` 技能的 `generate_article.py` 生成 HTML
- 默认主题：`tech-dark`（科技深蓝）
- 单发 HTML 文件（不打包、不带 PNG）

## 五种视频类型的标准结构

### 1. 纪录片/传记型
```
引子（场景/问题/反差）
├── 一、起源：背景 + 诞生过程 + 关键人物
├── 二、关键转折1：第一个重要节点 + 影响
├── 三、关键转折2：第二个重要节点 + 冲突/战争
├── 四、低谷：最困难的时期 + 原因
├── 五、重生/崛起：怎么走出来的 + 关键决策
├── 六、现状：今天怎么样了 + 最新进展
├── 七、深层洞察：为什么能成/为什么失败（提炼规律）
└── 结语：升华 + 留给读者的问题
```

### 2. 技术讲解型
```
问题引入（这个技术解决什么痛点）
├── 一、背景：问题的来龙去脉 + 现有方案的局限
├── 二、核心原理：这个技术的本质是什么
├── 三、技术细节拆解：关键机制/架构/算法（分点讲透）
├── 四、对比与定位：跟同类技术比怎么样
├── 五、适用场景与边界：什么时候用、什么时候别用
├── 六、实践/实测：真实使用体验/效果数据
└── 七、未来展望：发展方向 + 未解问题
```

### 3. 行业分析型
```
现象抛出（发生了什么事）
├── 一、数据全景：关键数据 + 市场规模 + 趋势
├── 二、驱动因素：为什么现在发生（技术/政策/需求）
├── 三、产业链影响：上中下游分别怎么变
├── 四、代表玩家：主要公司/产品/模式
├── 五、反方视角：风险、质疑、另一种可能性
├── 六、未来判断：短期/中期/长期趋势
└── 结语：对读者的启示/行动建议
```

### 4. 演讲/访谈型
```
核心观点（一句话提炼演讲/访谈的核心）
├── 一、背景：演讲者是谁、什么场合、为什么重要
├── 二、核心论点拆解：分3-5个主要观点展开，每个配原文引述+分析
├── 三、延伸思考：这个观点放在更大的背景下意味着什么
├── 四、反方意见：有没有人反对、反对理由是什么
├── 五、金句集锦：最有冲击力的5-10句原话
└── 结语：总结 + 评价
```

### 5. 多源综合型
```
总论点（把多个素材串起来的核心判断）
├── 分论点1 + 对应案例（来自素材A）
├── 分论点2 + 对应案例（来自素材B）
├── 分论点3 + 对应案例（来自素材C）
├── 综合分析：三个点放在一起说明了什么
├── 反方视角：有没有反例、有没有漏洞
└── 结论：总论点再升华 + 启示
```

## 质量检查清单（交付前必过）

**一票否决项（任何一条不过 → 直接重写，不交付）：**
- [ ] 段落是否成块？每段 200-400 字，有论点+论据+分析？（一句话一段 = 否决）
- [ ] 每章是否有一个核心论点？还是流水账式的时间线堆砌？（流水账 = 否决）
- [ ] 结构是否由素材形状决定？还是硬套模板？（模板痕迹明显 = 否决）
- [ ] 反方视角是否融入章节？还是单独切块像补丁？（补丁式 = 否决）

**常规检查项：**
- [ ] **事实零演绎**：所有具体事实（人物、数字、事件、原话）都能在字幕里找到
- [ ] **扩充已标注**：背景知识/分析/推理都有明确标示，没有跟原片事实混在一起
- [ ] **专业深度够**：不是复述内容，有技术拆解、有行业背景、有深层分析
- [ ] **逻辑通顺**：每个重要结论都有支撑，不是凭空喊口号
- [ ] **叙事流畅**：读起来不卡顿，过渡自然
- [ ] **字数达标**：4000-8000 字（特殊情况可调整）
- [ ] **HTML 已生成**：调用 ai-content-imagery 生成，主题正确

## 与 ai-studio 体系的关系

```
用户提供字幕文件
    ↓
video-to-deep-blog（本技能：字幕 → 专业深度长文 Markdown）
    ↓  Markdown 文件
ai-content-imagery（Markdown → HTML 页面）
```

- 与 `ai-content-production` 是**协作关系**：主技能做日常内容生产，本技能做深度长文内容
- 与 `ai-content-imagery` 是**上下游关系**：本技能产出 Markdown，imagery 负责渲染 HTML
- 与 `ai-content-metrics` 是**互补关系**：产出的文章数据进入 metrics 做复盘

## Pitfalls

- **不要依赖 YouTube API** ——用户说了字幕人工给，别去调 youtube-transcript-api
- **不要把猜测当事实** ——特别是对人物心理、未公开信息的脑补，一律禁止
- **不要写成字幕整理** ——读者要的是文章，不是 transcript 的分段版。要有主线、有分析、有洞察
- **不要只讲一面** ——再正确的观点，没有反方视角就会显得单薄
- **控制扩充比例** ——原片内容至少占 60%，补充内容不超过 40%，不然就不是"基于视频"了
- **技术术语要解释** ——专业优先不等于堆砌术语，第一次出现的术语要有简短解释
