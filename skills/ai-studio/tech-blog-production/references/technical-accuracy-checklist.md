# 技术严谨性自检清单

> 技术博客写完后，逐项对照检查。所有项必须通过才能交付。

---

## 一、定义准确性

- [ ] 文章中出现的核心技术概念，第一次出现时都有明确的定义
- [ ] 定义是准确的，不是模糊的描述（能经得起原文对照）
- [ ] 缩写第一次出现时写了全称
- [ ] 全文术语统一——同一概念没有混用不同说法

## 二、原理准确性

- [ ] 技术原理描述和原始论文/官方文档一致
- [ ] 没有为了通俗而歪曲技术事实
- [ ] 关键机制的描述有细节支撑（不是空泛的"很先进"）
- [ ] 涉及公式/算法时，是正确的（可以简化但不能错）

## 三、类比规范

- [ ] 每个类比后面都说明了"这个类比的局限/不准确的地方"
- [ ] 类比是辅助理解用的，不是替代技术描述
- [ ] 没有用类比推导结论（类比只能帮助理解，不能当论据）

## 四、数据与来源

- [ ] 所有技术参数、性能数据、规模数据都标注了来源
- [ ] 数据来源是可信的（官方 > 权威媒体 > 其他）
- [ ] 估算值明确标注了"估算"或"约"
- [ ] 没有凭空造数据、没有选择性引用有利数据

## 五、局限性与反方

- [ ] 讲了技术的局限性/适用边界
- [ ] 讲了已知的缺陷或未解决的问题
- [ ] 反方视角是真的有质量，不是稻草人
- [ ] 没有只说好的不说坏的

## 六、因果与判断

- [ ] 因果关系有依据，不是强行归因
- [ ] 判断有边界（说清楚什么情况下成立，什么情况下不成立）
- [ ] 标题断言级别 ≤ 证据级别（三级匹配制）
- [ ] 没有把相关性说成因果性

## 七、对比公平性

- [ ] 对比维度对双方公平（不是专门选某方擅长的维度）
- [ ] 对比的是同一级别的东西（不是拿旗舰比入门）
- [ ] 每个对比维度的数据都有来源
- [ ] 结论是基于对比的，不是预设的

---

## 快速检验法

读一遍文章，问自己三个问题：

1. **如果这篇文章的作者是我要挑战的人，我能指出多少技术错误？**
   - 能指出3个以上 → 回去改
   - 能指出1-2个 → 看严重程度
   - 指不出来 → 通过

2. **一个懂行的人读完，会不会觉得我是外行？**
   - 会 → 技术深度不够，回去补
   - 不会 → 通过

3. **有没有哪个地方是我不确定但写得很肯定的？**
   - 有 → 要么去确认，要么标注"推测"
   - 没有 → 通过
