# SFT 数据增强

定位：按评估报告对种子 QA 做分级扩充。专注增强本身——评估调 `sft-dataset-assessment`，全流程编步调 `sft-dataset-construction`。

## 何时用
- 有种子 QA，要扩充到可训练规模
- 评估后定向补强（类型失衡、定义缺失、拒答不足）
- 已有数据集质量不行，需要重做

## 设计铁律

1. **safe/full 两档**：safe=事实零新增（默认），full=推断/综合类需人工审核
2. **source 标记 + group_id 全程追溯**：每条带来源和出处组
3. **类型配额制**：自由反向生成会让 why/compare 类塌缩到 <1%，必须显式分配类型配额
4. **模板驱动 > 自由生成**：结构化输入+模板填空，失败率从 50%+ 降到接近 0
5. **宁缺毋滥**：纯规则层宁可产率低也要全对
6. **零失败尾巴**：失败条目必须 100% 补全，不静默跳过
7. **参数-实体绑定**：参数类答案首句必须重述归属（设备/部件），不能只答数值。中小模型实体绑定能力弱，解绑易被高频通用值顶替。
8. **反向题 ≥15%**：最终数据集中反向查询（特征→实体/代码/值/状态）占比不低于 15%。只教正向 = 反方向调用就张冠李戴。

## 9 阶段管线

| 阶段 | 名称 | 方法 | 事实新增 | 关键约束 |
|------|------|------|---------|---------|
| stage0 | 种子审计+建组 | 规则 | - | 清洗、建组、类型标注 |
| stage1 | L1 改写 | LLM | 无 | 类型保持、实体完整 |
| stage2 | L2 原子拆解+点查卡 | 纯规则 | 无 | 只拆参数列举型;**每个参数单独成一问一答**(点查卡);宁缺毋滥 |
| stage3 | L3 定向反向 | LLM/模板 | 无 | **反向题占比 ≥15%**(配额硬指标);类型含:实体检索/参数代号/状态判断/含义反查 |
| stage4 | L4 回答展开 | LLM | 无(safe) | 数值零新增校验;参数答案首句绑定实体 |
| stage5 | L5 约束指令+格式统一 | LLM/模板 | 无 | 格式规范:清单用 `1./2./3.`、定义用 `X 是...`、对比用 `A/B/区别:` |
| stage6 | L6 辨析+边界题 | 模板 | 无 | 易混对象对比题 + "不属于/排除项"边界题;每知识点至少 1 道 |
| stage7 | L7 拒答负样本 | LLM | 特殊 | 领域内越界问题,占比 0.5-1.5% |
| stage8 | L8 多轮对话 | LLM模板 | 无 | 模板填空 |
| stage9 | L9 定义类补全 | 规则+人工审 | 无 | 实体定义覆盖缺口审计后做;故障代码等必须设备绑定 |

> stage6 之前是辨析+边界题(本次新增)。stage6 之前的跨文档综合属 full 档,人工审核后并入,默认不开。

## 实体定义类补全（stage9）

先审计覆盖缺口，再补。按实体类型分别处理，难度差异极大：

| 实体类型 | 方法 | 质量 | 注意 |
|----------|------|------|------|
| 故障代码 | 规则提取 | 高 | **必须设备绑定**——同一代码不同设备含义不同。格式："在{设备}中，{代码}表示{含义}。" |
| 标准编号 | 规则提取 | 高 | 格式："{标准号}是《{名称}》的{国标/行标}编号。" |
| 润滑油牌号 | 规则提取 | 高 | 只留类型，删用量/配比等使用细节 |
| 部件/工艺术语 | 规则提取噪声大 | 低 | 规则提取存活率 ~30%，需人工终审 |

**教训**：固定格式抽取任务 → 规则秒杀 LLM（0.05s vs 300s 超时）。模板化输出优先用规则。

## LLM 批量生成工程

1. **断点续跑**：按 40/批执行，每批写 results + .done.json + .fail.json
2. **并发 3**：从 3 起步，高并发触发限流
3. **空 content 快速重试**：空串退避 0.4s 重试；仅 429/5xx 指数退避
4. **空 content 常是截断**：max_tokens 太小导致 finish_reason=length，提 max_tokens 解决（1024→1536），降温度是辅助
5. **JSON 三层容错解析**：直接解析 → 截取首尾括号 → 逐行提取对象
6. **失败升级阶梯**：同参重试 → 降温度+强制输出 → max_tokens 4096 → 单发+重试5次
7. **worker 透传错误类型**：401/429/5xx/空/超时 分类计数，便于区分 key 失效、限流、代码 bug
