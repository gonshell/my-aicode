# SFT 数据集质量评估

定位：对 SFT 数据集做质量评估，输出量化评分 + 缺陷报告。只读不改。

## 何时用
- 拿到一批数据，问"质量怎么样""能不能微调"
- 增强前后对比质量
- 输出缺陷清单指导后续增强

## 六层检测框架

| 层 | 名称 | 手段 | 垂域阈值 |
|----|------|------|---------|
| L1 | 完整性 | 规则 | 字段完整率≥99% |
| L2 | 一致性 | 规则 | 精确重复<3% |
| L3 | 多样性 | 统计 | 类型熵≥0.5，TTR≥0.15 |
| L4 | 正确性 | LLM抽检 | 4分通过率≥70% |
| L5 | 合理性 | emb/ppl(可选) | 语义重复<10% |
| L6 | 安全性 | 规则 | 敏感命中=0 |

执行顺序：L1/L2/L6（秒级规则）→ L3（统计）→ L4（LLM抽检，**跑前问用户**）→ L5（可选）

## L1-L3 规则层（必跑，零成本）

- 字段完整率 / 空值率 / 最小长度
- 精确去重（instruction+output 哈希）
- type 分布 / 长度分布 / source 分布
- 类型熵 / TTR / 长度 CV
- 敏感词 / 隐私正则

**坑**：短答案阈值按域校准。垂域参数类答案（"F04"、"≤4Ω"）是有效回答，<2字才删，<5字误杀。

## L4 LLM 抽检（可选）

- 三维评分：事实准确(50%) / 指令跟随(30%) / 答案完整(20%)，5 分制
- **核心指标是 4 分通过率**，不是平均分
- 分层抽样（按 source 分层），100-200 条够估计整体
- 低分样本召回归类：fact_error / off_topic / incomplete

**校准先行**：垂域短问答用"答对即完整"标准，否则一句话答对被判不完整（实测完整性 3.69→4.34）。校准前人工看 10-20 条低分样本。

**调用参数**：temperature 0.1，并发 3，失败重试最多 3 次。

## 原文回溯校验（有原文时必跑）

答案中最长连续片段（≥8字）回溯原文。按来源层设不同阈值：

| 来源层 | 预期匹配率 | 说明 |
|--------|----------|------|
| original / l2_split / l9_definition | ≥98% | 纯原文 |
| l1_rewrite | ≥95% | 改写不改事实 |
| l3_reverse | ≥85% | 答案是原文，问题新 |
| l5_constrained | ≥90% | 约束前缀，答案主体原文 |
| l4_expand | 不要求 | 推理展开不在原文是预期 |

**误报处理**：列表编号（"1.""2."）不算数值新增；合理同义改写用 6 字窗口重测。

## 输出：缺陷报告

```json
{
  "scores": {"L1": 4.9, "L2": 4.8, "L3": 2.6, "L4": 4.0, "L6": 5.0},
  "overall": {"score": 4.25, "grade": "A"},
  "defects": [
    {"id": "D1", "layer": "L3", "issue": "类型失衡: how 38% / compare 0.6%",
     "severity": "high", "evidence": "分布统计", "suggestion": "定向补 why/compare"}
  ],
  "coverage_gaps": [{"entity": "故障代码F01-F10", "gap": "无独立定义条"}]
}
```

缺陷必须带 evidence 和 suggestion，`sft-dataset-augmentation` 可直接消费。

## 场景权重模板

| 场景 | L1 | L2 | L3 | L5 | L4 | L6 |
|------|----|----|----|----|----|----|
| general | .10 | .15 | .20 | .15 | .30 | .10 |
| domain-fact | .15 | .25 | .10 | .10 | .30 | .10 |
| reasoning | .05 | .10 | .15 | .20 | .40 | .10 |
| chat | .05 | .10 | .20 | .20 | .25 | .20 |

等级：S≥4.5 / A≥4.0 / B+≥3.5 / B≥3.0 / C+≥2.5。
