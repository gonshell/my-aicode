## 工具盘点文（周一）

### 核心稿结构
```
【标题】N个免费好用的XX，第N个大多数人不知道
【一句话总览】（30字，为什么值得看）
工具1：名称
- 是什么（一句话定义）
- 能干啥（3-4个场景，每个一行）
- 为什么推荐（真实使用体验，1-2段）
- 适合谁 / 价格
工具2：...
...
结尾：怎么选建议 + 互动
```

### 平台改编要点

| 维度 | 头条 | 小红书 |
|------|------|--------|
| 标题 | 加数字+悬念 | emoji+感叹号+口语 |
| 段落 | 每个工具独立小节，有标题分隔 | 每个工具一个emoji编号+一段话 |
| 语气 | 聊天式，带情绪 | 闺蜜分享式 |
| 配图 | 工具截图+标注 | 封面=工具Logo拼接+大字标题 |
| 结尾 | 互动+引导关注 | 互动+10个标签 |

## 深度长文（周六）

### 核心稿结构
```
【标题】XX正在从"能用"变"好用"——但有一个致命盲区
【一句话结论】（50字以内）
一、事实部分：发生了什么 + 数据支撑（表格对比最佳）
二、为什么（分析原因，2-3个维度，每个带论据）
三、但是（反方视角/盲区/局限，这是重点，不写等于宣传稿）
四、对不同人的实际意义（分3类人群具体建议）
五、我的判断（未来6-12个月趋势，4-5条）
结尾：升华+互动问题
```

### 平台改编要点

| 维度 | 头条 | 小红书 | 公众号 |
|------|------|--------|--------|
| 字数 | ~2500字 | ~1000字 | ~3000字 |
| 标题 | 悬念+警示 | 对比+emoji | 专业+深度 |
| 结构 | 保留全部5段但缩短 | 每段缩成3-5行+emoji | 加深分析+加过渡 |
| 反方视角 | 独立成段"重点来了" | 用🔥/⚠️突出 | 融入分析中 |
| 人群建议 | 3段，emoji开头 | 同但更口语化 | 展开+更具体 |

### 表格使用技巧（深度文必备）
简单的markdown表格在头条和小红书上都有效。表格最能产生"对比锚点"效果，让抽象数据变得直观。

### 素材卡片模板

扫源时，每条素材按以下格式记录：

```

活料清单：
- 数字1：涨价15%，部分旗舰涨17%
- 数字2：1GW数据中心多花50亿美元
- 数字3：72GPU机架 700万→800万美元
- 原话："内存成本飙升逼涨硬件"
- 对比：今年三轮涨价（消费卡39%→专业卡翻倍→服务器17%）
- 反方：半导体周期涨跌都猛，可能强弩之末
形状判断：有数字+对比+反方 → 适合"故事+数字+反方视角"结构
适合哪些内容类型：工具盘点 / 实测体验 / 效率技巧 / 避坑指南 / 热点解读 / 深度长文 / 周盘点
```

### RSS 抓取代码（已验证，2026-08-23）

```python
import subprocess, xml.etree.ElementTree as ET

def fetch_rss(url, limit=5):
    r = subprocess.run(["curl", "-sL", "--max-time", "15",
        "-A", "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/125.0 Safari/537.36",
        url], capture_output=True, text=True, timeout=20)
    if r.returncode != 0 or not r.stdout.strip():
        return []
    root = ET.fromstring(r.stdout)
    # RSS 2.0
    items = root.findall('.//item')
    if not items:
        # Atom
        ns = {'atom': 'http://www.w3.org/2005/Atom'}
        items = root.findall('.//atom:entry', ns)
    results = []
    for item in items[:limit]:
        if item.tag.endswith('item'):
            title = item.findtext('title', '')
            link = item.findtext('link', '')
            desc = item.findtext('description', '')[:200]
        else:
            title_el = item.find('atom:title', ns)
            title = title_el.text if title_el is not None else ''
            link_el = item.find('atom:link', ns)
            link = link_el.get('href', '') if link_el is not None else ''
            summary_el = item.find('atom:summary', ns) or item.find('atom:content', ns)
            desc = (summary_el.text or '')[:200] if summary_el is not None else ''
        results.append({"title": title, "link": link, "desc": desc})
    return results

# 用法
feeds = [
    ("量子位", "https://www.qbitai.com/feed"),
    ("Simon Willison", "https://simonwillison.net/atom/everything/"),
    ("The Rundown AI", "https://www.therundown.ai/feed"),
    ("TechCrunch AI", "https://techcrunch.com/category/artificial-intelligence/feed/"),
]
for name, url in feeds:
    items = fetch_rss(url, limit=5)
    for item in items:
        print(f"【{name}】{item['title']} → {item['link']}")
```

### 从 RSS 标题到深度素材的抓取流程

1. RSS 给出标题和链接 → 确定哪篇值得深挖
2. 用 `curl -sL` 抓原文页面 → 用正则去 HTML 标签提取纯文本
3. 从纯文本里提取：具体数字、具体原话、对比数据、时间线
4. 如果原文有争议点或反方观点，笔记下来
5. 判断素材形状 → 选结构 → 搭骨架 → 写

### 实跑案例：2026-08-23 三篇素材的形变过程

| 素材 | 活料数量 | 素材形状 | 选的结构 | 最终标题 |
|------|----------|----------|----------|----------|
| 英伟达涨价 | 6个数字+1个反方 | 故事+数字+对比+反方 | 事件叙事体，内部带对比表 | "英伟达又涨价了，但这次不只是割韭菜" |
| 匿名模型Ox Alpha | 5个数字+2个指纹证据+1个反方 | 悬疑+技术细节+两方猜测 | 破案叙事体，指纹证据分列 | "一个匿名模型刷屏了，全圈都在破案" |
| DeepMind校友创业 | 3个事实+1个反方 | 反常识+小对大+有争议 | 故事+对比+泼冷水体 | "几十人的小公司，说自己在科研上赢了GPT-4o" |

写完后逐条检查：
- [ ] 每段第一句是结论吗？（不是"因为..."而是"X正在发生"）
- [ ] 数字有参照系吗？（"500B"要变成"=GPT-3的25倍"）
- [ ] 有反方视角/局限吗？（找不到=写得不够深）

- [ ] 标题有数字+悬念吗？（头条版）

## 论证骨架速查表（6种）

> 素材形状决定骨架形状，写之前先选骨架。

| 骨架名 | 结构 | 适用素材形状 | 标志性特征 |
|--------|------|-------------|-----------|
| **标准因果式** | 现象→原因→反方→判断→影响 | 单个事件/趋势，有因有果 | 最通用的五段式 |
| **对比式** | A全貌→B全貌→关键差异→各自优劣→我的判断 | 两个东西的比较（产品/路线/模式） | 有明确的对比双方 |
| **层层剥笋式** | 表面现象→直接原因→深层原因→根本矛盾→出路 | 有深层矛盾的顽疾/反复出现的问题 | 可以连续问三层"为什么" |
| **多方视角式** | 事件→A方立场→B方立场→C方立场→我的判断 | 有争议的事件，各方立场差异大 | 至少三方有明显不同的利益和观点 |
| **叙事体** | 背景→问题→关键转折→结果→启示 | 一个公司/一个人/一个产品的故事 | 有时间线、有戏剧性转折 |
| **多源融合式** | 事件A→事件B→事件C→合在一起看→核心判断 | 多个独立事件指向同一个趋势 | 至少3个独立来源的独立事件 |

> 可以嵌套使用：大骨架套小骨架。比如多源融合式的外层骨架里，每个事件内部用因果式展开。

## 头条信息流版写作模板（新增，2026-08-25）

> **适用场景**：今日头条 / 百家号等信息流平台发布
> **阅读场景**：手机端刷信息流，3 秒抓不住就划走
> **核心原则**：段落短、节奏快、信息点密集、每 2-3 段有一个加粗关键词

### 段落节奏标准

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 每段句子数 | 2-4 句 | **一句话一段 = 否决**（那是微博不是文章） |
| 平均段落长度 | 60-100 字 | 比深度长文短，但语义单元必须完整 |
| <50字段落占比 | ≤30% | 少量过渡句/金句可以短，大部分应该是完整段落 |
| 50-120字段落占比 | ≥60% | 主力区间 |
| >150字段落占比 | ≤10% | 控制长段，太长就拆 |
| 加粗密度 | 每 2-3 段有 1 个关键词加粗 | 加粗标名词/数字/核心词，不是整句加粗 |
| H2 标题数量 | 3-5 个 | 不用太多，自然过渡为主 |

> **常见错误**：把"信息流短文"理解成"一句话一段"。错。段落是语义单元，不是长度单位。短是相对于深度长文的 200-300 字而言，不是碎到一句话就切。

### 结构模板

```
【标题】L2 趋势级，从内容里长出来，不越级
【开头】直接给核心信息点，3 行内抓住人（不铺垫）

---

**第一个，[事件1核心]。**
（2-3 段讲清楚事实+关键数字）
（1-2 段讲原理/为什么重要）

---

**第二个，[事件2核心]。**
（同上节奏）

---

**第三个，[事件3核心]。**
（同上节奏）

---

## 放在一起看
（3-5 段归纳共同模式，不要上价值，就说事实层面的共同之处）

---

## 说几句冷静的
（反方视角/局限/风险，必须有）

---

## 为什么值得关注
（3 个原因，每个 2-3 段）

---

## 几个具体的观察
（对不同人群的建议，不用太展开）

---

*参考来源：...*
```

### 写作要点

1. **每段只说一件事**：一句话能说清的，就不要凑成一长段
2. **加粗给关键词，不给整句话**：加粗的是名词/数字/核心词，不是整句加粗
3. **用「---」分隔大段，不用 H2 堆层级**：信息流阅读不需要强层级感，分隔线就够了
4. **开头不铺垫**：不说"最近AI圈怎么样"，直接说"这周有三个进展，放在一起看有点意思"
5. **不做长表格**：能不用表格就不用，改用 bullet point 或者分段说
6. **结尾不升维**：不说"下半场开始了"这种大话，说一个具体的判断就好
7. **真实性红线不变**：标题三级制、断言-证据匹配、套话黑名单，全部适用

### 和深度长文版的对比

| 维度 | 深度长文版 | 头条信息流版 |
|------|-----------|-------------|
| 阅读场景 | 坐下来认真看 | 刷手机信息流 |
| 段落长度 | 150-300 字/段 | 30-50 字/段 |
| 信息密度 | 高，每段信息量大 | 高，信息点密集但每点小 |
| 结构感 | 强，H2/H3 多层级 | 弱，自然过渡 |
| 加粗 | 少，核心概念才加 | 多，关键词/数字都加 |
| 表格 | 多用，对比清晰 | 少用，改用列表 |
| 结尾 | 升维判断 | 具体观察 + 互动 |
| 适用平台 | 公众号/周末深度 | 头条/百家号/日更 |

## 微头条模板（新增，2026-08-27 实踩坑验证）

> **适用场景**：今日头条微头条、微博、朋友圈短评
> **阅读场景**：刷信息流，2 秒抓不住就划走
> **核心原则**：活料前置、观点浓缩、一句不多说、质量不降级

### 规格标准

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 字数 | 150-250 字 | 少了说不清楚，多了没人看完 |
| 段落数 | 1-2 段 | 不分小节，不加小标题 |
| 核心观点数 | 1 个 | 只讲透一个点，不说面面俱到的话 |
| 活料数量 | 至少 2 个具体数字/细节 | 微头条也必须有硬货 |
| 附录 | 完整质量说明 + 信息来源 | 质量标准不因篇幅短而降低 |

### 结构模板

```
【标题】一句话说清核心事件 + 最大的数字/反差
【正文】
第1句：抛最硬的料（事件+核心数字/反差）
第2-3句：补一个关键细节（原理/背景/趣味点，1句话说清）
第4句：给出一个明确观点（不模糊、不两面讨好）
第5句：互动钩子（问题/投票/你怎么看）

---
## 附录
### 一、内容质量说明（6项完整表格）
### 二、信息来源（2-3个权威来源，带链接）
```

### 写作要点

1. **第一句就有硬料**：不说"最近AI圈有个事"，直接说"千问办公昨晚首发Qwen3.8-Flash，速度+100%，Token-75%"
2. **每句话都增加信息量**：删掉所有不增加新信息的话——"值得注意的是""很多人不知道""换句话说"这类全删
3. **只讲一个点**：200字讲不清5件事，选最炸的那个讲透
4. **观点要明确**：不要"一方面/另一方面"，直接说"我认为这意味着……"
5. **结尾是钩子不是总结**：不要"总而言之"，要"你怎么看？""你遇到过吗？"
6. **质量附录不简化**：质量说明表格6项全填，信息来源2-3个带链接——微头条可以短，但不能水

### 和头条信息流版的对比

| 维度 | 头条信息流版 | 微头条 |
|------|-------------|--------|
| 字数 | 1500-3000字 | 150-250字 |
| 结构 | 5-8个小节，有标题层级 | 1-2段，无层级 |
| 核心观点 | 1个主线 + 多个分论点 | 只有1个核心观点 |
| 论据数量 | 3-10个 | 1-2个 |
| 反方视角 | 独立成段展开 | 隐含或一句话带过 |
| 附录 | 完整 | 完整（标准一样） |
| 生产时间 | 25-40min | 5-10min |

- [ ] 不超过 2 段吗？
- [ ] 第一句就有硬料吗？（数字/反差/悬念，没有铺垫）
- [ ] 有且只有一个核心观点吗？
- [ ] 删掉了所有不增加信息量的话吗？（"最近""值得注意的是""很多人不知道"等）

## 文末附录模板（每篇必附）

> 放在文章最后，`## 附录` 二级标题下分两节。

### 一、内容质量说明

| 项目 | 等级 | 说明 |
|------|------|------|
| **事实准确性** | A / B / C | A=多方信源交叉验证；B=单一可靠信源；C=有争议或细节待确认 |
| **断言强度** | L1 / L2 / L3 | L1=事实级（陈述发生了什么）；L2=趋势级（判断方向）；L3=颠覆级（推翻常识） |
| **证据匹配度** | 匹配 / 偏高 / 偏低 | 断言强度是否 ≤ 证据强度。匹配=合规 |
| **反方视角** | 有 / 无 | 是否呈现了反对意见或局限性 |
| **预测成分** | 高 / 中 / 低 | 文中预测/推断内容的比例 |
| **适用范围** | （一句话） | 结论在什么范围内成立 |

> 填写说明：根据实际情况选等级，不要全填 A / L3 / 匹配。如实反映质量边界。

### 二、信息来源

每条来源三要素：来源名称 + 文章标题 + 原始链接。

格式：
```
- **来源名称**：文章标题
  链接：https://...
```

## 真实性自检清单（必过）

> 来自 ../../shared/RULES.md「断言与证据匹配」。每篇发出前过一遍，不过就改。

- [ ] **标题越级了吗？** L1 事实级随便写；L2 趋势级需要 A 级证据+合理因果链；L3 判断级（"改变了""下半场"）需要 S 级证据+市场验证+多个案例
- [ ] **断言强度 ≤ 证据强度吗？** 强断言（"X打败了Y"）需要 S/A 级证据 + ≥2 个独立来源；证据只有 B 级就只能说弱断言
- [ ] **有套话空话吗？** 过一遍套话黑名单（颠覆认知/很多人不知道/信号很明确/下半场开始/改写规则/革命/炸裂/再不...就晚了），有就替换或删掉
- [ ] **"三个突破"不等于"行业变天"**：实验室结果 ≠ 市场验证 ≠ 行业改变。从实验到行业中间差好几个台阶，不能直接跳
- [ ] **区分事实和判断**：事实是"4-bit模型在7/9基准上超过全精度版"，判断是"这意味着效率方向在加速"。判断要明确标示，不要混在事实里
