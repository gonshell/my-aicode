# AI 资讯内容生产与三平台分发

## 核心概念

### 读者定位（必须明确，否则内容方向漂移）

- **目标读者**：想靠 AI 提效的职场人 + 中小创业者（B2 侧专业读者为主）
- **不是**：普通大众（抢不过量子位/36氪的流量）或研究者（盘子太小）
- **涨粉+变现路径**：流量费（起步）→ 工具推荐佣金 → 品牌广告 → 社群/课程。前期只盯数据（完读率/互动率/收藏率），不盯收益
- **投入约束**：日均 1h + 周末 3-4h

### 一鱼三吃（本技能独有的生产模式）

**核心稿（25min）→ 多平台改编（各5-10min），不是写多篇**

```
原始素材（15min 扫源选1个选题）
    ↓
核心稿（800字：事实+分析+判断）
    ├→ 头条长文（短段落+高加粗+互动）← 10min
    ├→ 微头条 × 2-3条（200字/条，不同角度）← 5min/条
    ├→ 小红书版（图文+口语化+标签）← 10min
    └→ 公众号版（周末深度+体系感）← 15min
```

**周末**：3-4h 写深度长文 + 下周选题储备 + 数据分析复盘

**微头条定位**：不是"短版长文"，是独立内容形态。150-250字、1-2段、活料前置、观点浓缩、质量标准不降级（附录完整）。一篇长文可以拆出2-3条微头条，每个讲一个侧面，矩阵发布。

### 信息源分层（来自 19 个已验证源）

| 层级 | 用途 | 源 | 频率 |
|------|------|-----|------|
| L1 每日必扫 | 选题来源 | 量子位、Simon Willison、The Rundown AI、TechCrunch AI | 每天早上 10min |
| L2 按需深读 | 深度素材 | MIT TR、Ars Technica、Hugging Face Blog、VentureBeat、The Verge | 每周 2-3 次 |
| L3 周度盘点 | 周更素材 | The Batch、Import AI、新智元、AI Business | 每周五/日 |
| L4 触发式阅读 | 大事件才看 | DeepMind、Lil'Log、OpenAI/Anthropic 官博、MarkTechPost、Wired | 事件触发 |

### 三平台定位

| 平台 | 角色 | 收益模式 | 内容形态 | 起号周期 |
|------|------|----------|----------|----------|
| 今日头条 | 跑量主力 | 流量费 10-50元/万阅读 | 800-2000字中长文 | 1-2月 |
| 小红书 | 涨粉+广告 | 品牌广告 30-100元/万阅读 | 6-9图+300-600字短文 | 2-3月 |
| 公众号 | 私域沉淀 | 长期价值 | 1500-3000字深度文 | 3-6月 |

## 工作流

### 启动强制步骤（任何 AI 内容生产任务第一步必须做）

1. 执行素材采集：先跑 `scripts/fetch-ai-materials.py`（或等价的 RSS 抓取代码），扫完所有 L1 源
2. 选题从 RSS 条目里选，主素材从 RSS 条目链接的原文深挖
3. 搜索工具（qwen/searxng 等）只能用于补充素材，**不能作为主素材来源**
4. 例外情况（可以不用 RSS 直接搜索）：
   - 用户明确指定了数据源/链接
   - 用户指定的主题在 RSS 源中确实没有相关素材（需在交付时说明）
   - 用户明确要求用搜索

### 每日 1 小时

| 步骤 | 耗时 | 动作 |
|------|------|------|
| 选题+扫源 | 15min | 扫 L1 源（4个），选 1 个核心选题，提取活料（数字/原话/细节） |
| 选骨架+搭论证链 | 5min | 根据素材形状选骨架类型，搭出核心行文逻辑链条 与 目录结构 |
| 核心稿写作 | 20min | 按骨架填血肉，每个论点配具体数字或原话 |
| 头条长文改编 | 10min | 改标题（按标题三级制选）+ 拆短段落 + 加粗关键词 + 加互动 |
| 微头条改编 | 10min | 从核心稿提炼2-3个角度，每个角度1条微头条（200字/条） |
| 小红书改编 | 10min | 截3-6图+做封面+口语化+标签 |
| 生成HTML | 5min | 调用 imagery 生成脚本，头条版默认用 `plain` 主题，公众号版用 `wechat-light` 主题 |
| 真实性自检 | 5min | 过 shared/RULES.md 真实性红线 + 写作质量底线 + 本技能自检清单 |

## 核心生产哲学：素材驱动，不是模板驱动

### 最根本的问题：内容为什么呆板？

用户明确指出：**"太呆板"、"不能直接给用户看"、"目录结构能否根据要写的内容来定？"、"能否找真实数据源来写而不是臆测？"**

呆板的根源是**模板驱动**——先选模板类型，再往模板里填通用内容。结构是预设的，血肉是虚构的，所有文章看起来都差不多。

### 解决方案：素材驱动

**先有真实素材（具体的人/事/数字/原话）→ 素材本身决定写什么、怎么组织 → 模板只起"基本质量底线"的作用，不是牢笼。**

#### 第一步：抓素材时抓"活料"，不是干料

| 干料（呆板的根源） | 活料（让文章鲜活） |
|---------------------|---------------------|
| "某某公司发布了新模型" | "这个模型在 XX 测试上比前代高了 15.3 分，但延迟涨了 42%" |
| "博主实测后评价很好" | "Simon Willison 说：'我把整个项目代码丢进去，它直接写出了能跑的代码'" |
| "融资很多" | "融了 2.3 亿美元，投资方是红杉，估值比上轮翻了 3 倍" |
| "效果很好" | "在 200 道算法题上，正确率从 62% 提到了 78%" |

**铁律：每个素材点必须带至少一个具体数字或一句原话。** 没有的话，这个素材就不够"活"，要么深挖原文，要么不用。

#### 第二步：用 execute_code 从 RSS 抓真实素材

```python
import subprocess, xml.etree.ElementTree as ET

url = "https://www.qbitai.com/feed"  # 或 Simon/TC/Rundown 等
r = subprocess.run(["curl", "-sL", "--max-time", "15",
    "-A", "Mozilla/5.0 ...Chrome/125.0", url],
    capture_output=True, text=True, timeout=20)
root = ET.fromstring(r.stdout)
items = root.findall('.//item')  # RSS 2.0
# 或 root.findall('.//atom:entry', ns)  # Atom
for item in items[:5]:
    title = item.findtext('title', '')
    link = item.findtext('link', '')
    # 然后抓原文深挖具体数字和原话
```

**已验证可用的 RSS 源（2026-08-23 实跑）：**
- 量子位：https://www.qbitai.com/feed（中文，日常热点）
- Simon Willison：https://simonwillison.net/atom/everything/（工具实测，技术向）
- Hugging Face Blog：https://huggingface.co/blog/feed.xml（技术博客，周更）
- The Rundown AI：https://www.therundown.ai/feed（每日策展，商业向）
- TechCrunch AI：https://techcrunch.com/category/artificial-intelligence/feed/（创业融资）

#### 第三步：根据素材的"形状"选结构，不是先定结构再找素材

**素材形状决定文章形状：**

| 素材形状 | 适合的结构 | 可用的结构原子 | 不用的结构 |
|----------|------------|---------------|------------|
| 一个东西的多个维度 | 清单体/盘点体 | 工具盘点模板 | 叙事体 |
| 新旧对比 / 多方对比 | 对比体 | 深度长文模板（事实→原因→局限→判断） | 清单体 |
| 一个事件+各方反应 | 多方视角体 | 事实→A方→B方→我的判断 | 叙事体 |
| 一个问题的层层深入 | 层层递进体 | 表面→深层1→深层2→根本→怎么办 | 盘点体 |
| 一个人的故事/产品的诞生 | 叙事体 | 背景→问题→解决→结果→启示 | 对比体 |
| 多个独立热点事件 | 事件盘点体 | 总览→事件1/2/3→串起来看→建议 | 深度长文体 |

**关键认知：模板不是 5 个固定格式，而是一组"结构原子"，根据素材自由组合。** 参考 `references/verified-writing-templates.md` 中的结构原子库。

#### 第四步：写作时"用素材说话"，不是"用观点说话"

❌ 呆板写法（观点）：
> "开源模型进步很快，正在逼近闭源。"

✅ 鲜活写法（事实）：
> "一年前开源模型和 GPT-4 还差两代，现在代码任务只差 2-7 分了——MMLU 从 72 分爬到了 86 分，而 GPT-4o 是 92 分。"

**原则：让读者从事实里自己得出结论，比你直接告诉他结论，说服力强 10 倍，也鲜活 10 倍。**

#### 改造后的工作流

```
1. 扫源（15min）
   不是只看"有什么事"，而是抓"活料"：
   - 具体数字
   - 具体原话（名人/博主/官方）
   - 具体对比数据
   - 具体场景和例子
   每条素材存成卡片：标题 + 3-5个活料点 + 来源链接

2. 选题判断（5min）
   不是"这个话题热不热"，而是：
   - 这个素材的活料够不够？（至少3个具体数字/原话/细节）
   - 素材的形状适合什么结构？（清单体/对比体/叙事体…）
   - 读者会关心吗？

3. 搭骨架（5min）
   根据素材形状，选结构原子，搭出这篇的专属目录
   不是套模板，而是"这篇有3个数字对比+1个争议点 → 用对比体+反方视角"

4. 填血肉（20min）
   用活料填进去——每个论点配一个具体数字或原话
   每个段落第一句是结论，后面紧跟事实支撑

5. 平台改编（各10min）
   标题/格式/语气按平台调，但核心素材不变
```

### 实跑验证：素材驱动 vs 模板驱动对比

| 维度 | 模板驱动（第一版） | 素材驱动（第二版） |
|------|-------------------|-------------------|
| 第一步 | 先选模板类型（盘点/实测/深度…） | 先抓真实素材，提取活料（数字/原话/细节） |
| 结构 | 模板预先定死 | 素材的形状决定文章的形状 |
| 内容 | 通用分析+观点为主 | 具体事实+数字+案例驱动观点 |
| 呆板感 | 明显（都一个模子刻出来的） | 低（每篇根据素材自然长出来） |
| 用户评价 | "太呆板" | 待验证 |

### 文字质感提升清单

目标不是"伪装成不是AI写的"，是写得好、有力量、读着顺。以下6条，按重要性排序。

**1. 段落成块，禁止碎片化（公众号深度文适用）**
- 每段200-400字，围绕一个核心论点展开
- 段落结构：论点 → 论据（事实/引语/数据）→ 分析，三层完整
- 段与段之间有逻辑衔接，不是独立点的罗列
- **注意：头条版不适用此规则**。头条信息流内容要求70%段落<50字，平均38字/段，高频加粗、少标题层级、对话感强。见 `references/multi-platform-content-adaptation.md` 中的头条排版特征数据

**2. 句子长短交错，打破均匀节奏**
- 每3-5个长句配1个短句（10字以内）
- 节奏变化比"口语化"重要10倍
- 允许反问句、插入语、破折号打断——但要克制，不能为了变而变
- 检验方法：随便摘一段话，数句子长度，如果都差不多长，就是节奏死了

**3. 砍掉80%的连接词和路标句**
- 以下词汇能砍就砍：首先/其次/最后、值得注意的是、更有意思的是、核心问题是、由此可见、综上所述
- 靠内容本身的逻辑推进，不靠词语宣告逻辑
- 检验方法：删掉连接词如果读者看不懂——不是连接词的问题，是段落之间的逻辑本身就弱

**4. 每篇至少一个明确的判断**
- 不要永远"一方面/另一方面"的平衡
- 有一个敢站边的判断，比十个模棱两可的分析有力量
- 判断可以有反方视角，但判断本身要清晰
- 怕错不是缺点，含糊才是

**5. 标题服务于内容，不服务于结构**
- 标题的作用是帮读者定位重点，不是给文章打格子
- 如果标题下面第一段话就是在重复标题的意思，那这个标题是多余的
- 没有固定数量要求——该加就加，不该加就不加
- 深度技术文可以标题多，头条短评可以标题少，看内容需要

**6. 结尾落地，不喊口号**
- 不空泛升华（"每个行业都会经历这个阶段"）
- 落在一个具体的问题、一个具体的画面、一句让人记住的话上
- 好结尾是"留钩子"，不是"做总结"

> **补充说明**：这个清单替代了原来的"六个基本原则"。原来那版偏"内容质量"（结论倒挂、对比锚点这些），新版偏"文字质感"（节奏、力量、味道）。两个维度不一样，都重要。

### 头条标题公式
> **真实性约束**：标题断言级别不得超过内容证据级别（见 shared/RULES.md 标题三级匹配制）。反常识型必须有具体数据支撑，不是自己造的反差。

- 数字清单型："N个XX神器，最后一个绝了"
- 反常识型："别再XX了，真正的XX是XX" → 反常识点必须有数据支撑
- 亲测型："我XX了一周，真实感受"
- 对比型："XX vs YY，差距比想象的大" → 差距必须有具体数字
- 警示型："XX正在发生，再不XX就晚了" → 禁止制造焦虑，必须有真实风险

### 小红书封面规范
- 字必须大（手机一眼看清）
- 有数字（3个/5个/10秒）
- 有对比（前vs后/错vs对）
- 颜色对比强（黑底白字/红底白字）
- 真实截图 > 设计图（信任感更强）

### 写作模板（已验证可复用）

#### 工具盘点文模板（周一）
```
【标题】N个XX神器，最后一个绝了
开头（3行抓眼球，痛点+预告）
正文：每个工具=名称+一句话+核心亮点+适合谁+价格
结尾：推荐Top1+互动（"你用过哪个？评论区聊聊"）+引导关注
```

#### 深度长文模板（周六）
```
【标题】XX正在发生，但有一个致命盲区
一句话结论（50字以内）
一、事实部分：发生了什么 + 数据支撑
二、为什么（分析原因，2-3个维度）
三、但是（反方视角/盲区/局限）
四、对不同人的实际意义（分人群建议）
五、我的判断（未来6-12个月趋势）
结尾：互动问题
```

#### 周盘点文模板（周日）
```
【标题】本周AI圈N件大事，第X件影响最大
一句话总览（30字）
N个事件：每件=事实（3行）+为什么重要（2行）+我的判断（1行）
趋势总结：串起来看的核心判断
分人群建议：程序员/产品/普通人
结尾：互动+关注
```

## 进阶：专业深度写作范式

> 本技能遵循 ai-studio 体系共享规则（见 `../shared/RULES.md`）：
> 事实零演绎、专业优先、有推理链、有反方视角、可溯源。
> 以下是本技能特有的写作方法和结构范式。

> 适用场景：周末深度长文、技术分析类内容
> 目标读者：AI 从业者 / 技术管理者 / 对 AI 有基础认知的人
> 核心原则：**专业优先，在此基础上做到易懂**

### 什么是「专业」

不是堆砌术语，也不是写得晦涩。
专业 = **信息密度高 + 逻辑链条完整 + 有行业上下文 + 有独立判断**。

具体标志：
- 每个关键判断都有技术原理或行业事实支撑
- 不只说「是什么」，还说「为什么」和「意味着什么」
- 能把一个事件放到更大的行业脉络里，而不是孤立地看
- 有分层：表面现象 → 技术原因 → 产业影响 → 深层问题
- 反方视角不是应付，是真正有质量的对立观点

### 论证结构工具箱

素材驱动解决了「写什么」，论证结构解决「怎么串起来」。素材形状决定了用什么结构原子，论证结构决定了这些原子怎么推进、怎么咬合，才不会读起来散。

**这不是模板，是逻辑推进的四种基本模式。** 可以组合使用——比如一篇多源融合文里，每个事件内部用因果递进式展开。

#### 模式一：因果递进式

**适用场景**：单个事件的深度分析（一个大新闻、一个新产品、一个趋势）。
**核心逻辑**：从现象往里挖，一层比一层深。

```
现象（发生了什么，关键事实）
    ↓
直接原因（最表层的理由）
    ↓
深层原因（为什么这个理由会成立，行业/技术背景）
    ↓
影响（这件事会导致什么，短期/中期）
    ↓
判断（你的结论，敢站边的那种）
```

**常见错误**：每一层之间没有真的"递进"，只是换了个说法重复同一件事。检验方法：把每一层的第一句话摘出来，如果能连成一条"为什么→为什么→为什么"的链条，就是真递进；如果是平行的，就是假递进。

#### 模式二：多源融合式

**适用场景**：多个独立事件但指向同一个方向（两个新闻放在一起看，你发现了一个共同趋势）。
**核心逻辑**：分述 → 合观 → 升维。

```
事件A（事实 + 单独分析）
事件B（事实 + 单独分析）
    ↓  （放一起看）
共同模式（A 和 B 共同说明了什么）
    ↓
核心判断（这个模式意味着什么）
```

**常见错误**："合在一起看"那一段太弱，只是把两个事件各复述了一遍然后说"都很重要"。真正的多源融合，合观部分必须说出任何一个单独事件都说不出来的东西——1+1 要大于 2。

#### 模式三：辩证推进式

**适用场景**：有争议、有两面性的话题（比如某个政策、某个产品的功过、某个趋势的好坏）。
**核心逻辑**：先说A面，再说B面，最后给出C面——被双方都忽略的第三点。

```
主流观点（大家通常怎么看，论据是什么）
    ↓
反方视角（反对的声音是什么，论据是什么）
    ↓
第三点（被双方都忽略的东西 —— 这是全文最有价值的部分）
    ↓
判断（综合三方之后，你站哪边，为什么）
```

**常见错误**：第三点太软，只是"我们要辩证地看"这种废话。第三点必须是一个具体的、大多数人没想到的观察——如果正反两方听完都得愣一下，才是好的第三点。

#### 模式四：层层剥笋式

**适用场景**：有深层矛盾的问题（一个行业的顽疾、一个反复出现的现象）。
**核心逻辑**：一层一层往里剥，直到摸到根。

```
表面现象（所有人都能看到的）
    ↓
下一层（为什么会有这个现象，直接机制）
    ↓
再下一层（为什么这个机制会存在，结构性原因）
    ↓
根本矛盾（最底层的、暂时无解的那个矛盾）
    ↓
出路（在根本矛盾无解的前提下，能做什么）
```

**常见错误**：剥到第三层就停了，不敢碰根本矛盾——因为根本矛盾通常是不舒服的、没有完美答案的。但恰恰是这一层，区分了"深度文"和"新闻综述"。

#### 怎么选模式？

看素材的形状，也看你想回答的问题：

| 你想回答的问题 | 适合的模式 |
|-------------|-----------|
| 这件事到底怎么回事？ | 因果递进式 |
| 这几件事放在一起意味着什么？ | 多源融合式 |
| 这件事到底是好是坏？ | 辩证推进式 |
| 这个问题的根子在哪？ | 层层剥笋式 |

**素材形状和论证结构要匹配**——一个孤立的热点事件别硬套层层剥笋式，三个独立事件别硬套因果递进式。硬套的结果就是别扭、散、不体系。

### 专业深度文的标准结构（可灵活调整）

```
摘要（100字以内：这篇文章说了什么、核心结论是什么）
  │
  ├─ 一、事件回顾 / 事实部分
  │    把基本事实说清楚，给不了解的读者铺垫
  │    关键数字、关键人物、关键时间点
  │
  ├─ 二、技术根源 / 原理拆解
  │    这件事为什么会发生？技术上的原因是什么？
  │    用类比+技术细节结合的方式，让专业的人看到深度，不懂的人也能看懂
  │
  ├─ 三、更广阔的视角 / 行业全景
  │    不是某一家的问题，是全行业的共同困境
  │    横向对比：各家情况怎么样？
  │    纵向对比：历史脉络是怎样的？现在处于什么阶段？
  │
  ├─ 四、深层问题 / 本质矛盾
  │    往最底层挖一步
  │    这件事暴露了什么根本性的、暂时无解的问题？
  │    （这一段是区分「深度文」和「新闻综述」的关键）
  │
  ├─ 五、可能的出路 / 应对方向
  │    分层面说：技术层面、制度层面、行业层面
  │    不说空话，每个方向说具体做什么
  │
  └─ 六、对不同角色的建议
       开发者 / 公司 / 投资者 / 监管者 / 普通用户
       每个人能从这件事中得到什么行动指引
```

**注意：这是参考框架，不是铁律。** 根据素材形状调整——素材适合叙事就加叙事章节，素材有争议就加正反方辩论章节。结构永远服务于内容。

### 写作技巧：专业又易懂的平衡

**1. 先给结论，再展开推理**
- 每段第一句就是这一段的结论
- 专业读者看到结论就知道这一段在说什么，可以选择深读或跳过
- 普通读者也能快速抓住要点

**2. 技术细节 + 类比解释并行**
- 先讲技术细节（满足专业读者）
- 然后用一个类比让非专业读者也能理解
- 例如：「RLHF 本质是训练奖励模型给回答打分……打个比方，就像训狗，坐下就给肉吃」

**3. 信息密度要高，但节奏要有变化**
- 连续 2-3 段高密度技术分析后，插一个总结段或一个类比段
- 表格、列表、加粗金句，都是调节奏的工具
- 不让读者一直处于「费劲理解」的状态

**4. 引用原文原话 + 数据**
- 关键人物的原话直接引，用引用块
- 关键数字加粗，给参照系（「30% → 100%，翻了三倍多」）
- 专业文的可信度，很大程度来自「有据可查」

**5. 结尾要有升维**
- 不是重复前面说过的话
- 是把整篇文章的核心判断，提炼成一个更本质的问题或观察
- 让读者读完后记住一句话、一个画面

### 翻译改写类内容的生产流程

当素材是一篇高质量英文报道（如 TechCrunch、The Verge、Ars Technica）时，可以用「翻译改写」模式：

**不是直译，是基于原文事实的中文专业重构：**

1. **通读原文**，提取所有硬事实（数字、原话、事件、时间、人物）
2. **判断素材形状**：这篇适合什么结构？（叙事/分析/调查/对比）
3. **重组结构**：不是按原文顺序逐段翻译，而是按中文读者的阅读习惯重新组织
   - 英文新闻常用「倒金字塔」（最重要的放最前面）
   - 中文深度文更适合「层层递进」（现象→原因→影响→本质）
4. **补充背景**：原文默认读者知道的背景知识，中文读者可能不知道，需要补上
   - 比如 RLHF 是什么、Constitutional AI 是什么
   - 相关事件的来龙去脉
5. **加入分析**：不只是转述，要有自己的判断和串联
   - 这件事放在更大的行业图景里意味着什么？
   - 原文没说透的，能不能再往下挖一层？
6. **保留所有事实的来源标注**：末尾列参考来源

**红线：所有硬事实必须来自原文或可溯源的一手资料，不做演绎、不编造数据。** 分析和判断是作者的增值，但事实必须有出处。

### 多源融合：把多个事件串成一个主题

当有多个独立事件但指向同一个方向时，可以做「多源融合深度文」：

**核心思路：多个独立证据 → 汇聚成一个核心判断。**

操作步骤：
1. **扫源时注意「关联性」**：不只是找单个有料的事件，还要看几个事件之间有没有共同主题
2. **提炼核心判断**：这几个事件放在一起，共同说明了什么？
3. **每个事件作为一节**：每一节讲清楚一个事件的事实+分析
4. **专门有一节「合在一起看」**：把几个事件串起来，指出共同的模式
5. **结尾升维**：从这个共同模式出发，讨论更本质的问题

**示例**：Nvidia harness 研究 + 前沿实验室失控预案评估 + Anthropic 安全绕过事件
→ 共同主题：「能力在狂奔，安全在散步」
→ 结构：三个事件各一节 + 系统性失衡一节 + 出路一节 + 建议一节

多源融合的好处：
- 信息密度更高（一篇顶三篇）
- 说服力更强（多个独立证据指向同一个结论）
- 立意更高（不是报道单个事件，而是揭示行业趋势）

### 专业深度文的选题判断三问

1. **这个话题有「深度可挖」吗？** → 只有表面新闻、没有深层原因的，不适合做深度文
2. **我能找到足够的一手素材吗？** → 只有二手转述、没有原文/数据/研究的，写不出真正的专业感
3. **目标读者会关心吗？** → 太偏门的技术细节，受众太小，投入产出比低

三个都满足 = 值得写深度长文。
满足 1-2 个 = 可以写短一点的分析文。
只满足 1 个 = 放弃，或写成普通新闻快讯。

## 选题判断三标准

遇到一个素材，问自己三个问题：

1. **读者会关心吗？** → 跟普通人/职场人有关系吗？
2. **有冲突/反差吗？** → 反常识？有对比？有数据支撑的反差？
3. **我能写出独特视角吗？** → 不是搬运，有实测/有判断/有实操？

三个都满足 = 必写。满足两个 = 可以写。只满足一个 = 放弃。

## Pitfalls

1. **前1个月别盯收益，盯数据**：头条看阅读量/完读率/互动率，小红书看点击率/收藏率/涨粉数。找到爆款公式后猛做同类型。
2. **三平台不要一模一样发布**：标题必须改（不同平台吃不同钩子），格式必须改（头条长文/小红书图文），但核心内容可复用。
3. **每天1小时是紧的，别追求完美**：先完成再优化，稳定更新 > 偶尔精品。前20篇都是练手。
4. **信息源不直接刷19个**：用策展源当过滤器（The Rundown + Simon + The Batch），减少80%噪音。
5. **别用"网络受限"当借口**：信息源RSS地址已知时，直接用web_extract抓取。演示可以跑通，实战时替换真实素材即可。
6. **不要用 humanizer 技能改深度文/头条文**：该技能目标是"不被检测出AI写的"（evade detection），不是"提升文字质感"。用它改行业分析/头条深度文会砍掉骨架（标题被稀释、判断被软化、专业感被口语化冲淡），使文章变软变散。文字质感用本技能的「文字质感提升清单」自查，不要用去AI检测工具重写。
7. **不要写得呆板**：用户明确说过"不能写的太呆板"、"不能直接给用户看"。呆板的根源是模板驱动。每篇必须：
   - 素材驱动：先抓真实素材（RSS 抓取原文 → 提取具体数字/原话/细节），再让素材形状决定结构
   - 三个必有：每篇必须有具体数字、有对比锚点、有反方视角
   - 开头检查：不是"本文介绍了XX"而是"你有没有过这种经历"
   - 写完自查：读一遍，如果感觉像"模子里刻出来的"，说明素材不够多、不够活，回去深挖原文加分
8. **标题不得越级（真实性红线）**：用户明确反感夸大其词、套话空话。标题断言级别必须 ≤ 内容证据级别（见 shared/RULES.md 标题三级匹配制）。L2 趋势级需要 A 级证据+因果链，L3 判断级需要 S 级证据+市场验证。拿不准就降级，宁弱勿强。
9. **HTML 是默认交付物，不是可选**：写完 md 不叫完成，生成 HTML 才叫完成。头条版和公众号版默认都要出 HTML。调用 `ai-content-imagery/scripts/generate_article.py`，不要等到用户说"出HTML"才做。
10. **目录结构根据素材定，不是根据模板定**：用户明确说"目录结构能否根据要写的内容来定？"——三个热点事件就用盘点体，一个深度话题就用层层递进体，不要硬套固定模板。
11. **段落是语义单元，不是长度单位**：用户明确纠正"一句话一段"的做法。每段 2-5 句，围绕一个核心意思展开。信息流≠碎片化，不要为了"短"把一句话切成一段。
12. **微头条 ≠ 短版长文**：微头条是独立内容形态，不是把长文截短。150-250字、1-2段、活料前置（第一句就抛硬料）、只有一个核心观点、结尾留互动钩子。但质量标准不降级——质量说明表6项 + 信息来源2-3个带链接，和长文完全一致。参考 `references/verified-writing-templates.md` 中的微头条模板。
13. **写之前先搭论证骨架**：写正文之前，选骨架 → 填完 argument-skeleton.md 的五个框（核心论点→论据→反方→让步→结论）。骨架顺了再动笔，不要边写边想。这是用户明确确认的流程。
14. **不要停下来问确认，按技能走完**：技能写好了就按流程走完，不要停下来问用户"这样行不行""能继续吗"。用户明确纠正过这个行为。不确定的事先做一个合理默认选择，继续推进。

## 技能生态：ai-studio 三技能协作

本技能是 `ai-studio/` 分类下的主入口，另外两个配套技能分工如下：

```
ai-content-production（本技能，主入口）
    │
    ├─→ ai-content-imagery — 配图/封面/长图生成
    │     职责：HTML模板·Playwright渲染·各平台规格·版权规则
    │     调用时机：内容写完后，需要配图/封面/长图时
    │     接口：传内容数据 + 模板名 + 平台 → 返回 PNG 图片
    │
    └─→ ai-content-metrics — 数据复盘与优化
          职责：三平台指标体系·爆款归因·选题命中率·A/B测试
          调用时机：周复盘/月复盘，或需要分析内容表现时
          接口：传内容数据 + 文章清单 → 返回复盘报告 + 优化建议
```

**协作原则：**
- 用户只需要记住主技能，配图和复盘是主技能自动调用的
- 职责不交叠：生产不管渲染细节，配图不管选题策略，复盘不管写作方法
- 渐进式建设：主技能先跑通 → 配图跟上 → 有数据了再用复盘
