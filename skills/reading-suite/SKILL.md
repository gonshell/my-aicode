# Reading Suite — 完整知识管理工作流

## 设计哲学

基于以下验证过的方法论：
- **卢曼卡片盒笔记法** — 阅读与整理分离，原子化知识单元
- **对话式认知** — 知识是你和AI讨论出来的，不是AI写给你的
- **熵增对抗** — 定期全局维护是知识库长期可用的唯一方法
- **硬约束原则** — 角色边界必须是硬的，不能靠自觉

## 三种工作模式（自动识别）

| 模式 | 触发场景 | 核心功能 |
|:----|:---------|:---------|
| 📖 **阅读模式** | 读一篇新文章，或者继续之前的阅读 | 四角色对话系统 + 四层锚点记录 + 断点续读 |
| 🃏 **卡片模式** | 读完后提取可复用的知识单元 | 交互式拆分 + 相似度去重 + 反向链接 |
| 🔍 **复盘模式** | 定期全局检查优化 | 重复/冲突/盲区识别 + 交互式逐个处理 |

## 四角色对话系统

所有角色的约束都是硬编码检查的，不通过就重写，不可绕过。

| 角色图标 | 角色名称 | 触发语 | 核心约束 |
|:--------|:---------|:------|:---------|
| 🧑‍🤝‍🧑 | 思考伙伴（默认） | 正常对话 | 不能替你下结论，不能说"你应该" |
| 😈 | 魔鬼代言人 | "挑挑毛病"、"唱个反调" | 每个质疑必须锚定到原文具体位置，不能空泛 |
| 👨‍🏫 | 苏格拉底辅导员 | "引导我想想"、"别给答案" | 必须以问题结尾，不能直接给答案 |
| 🔬 | 同行评审 | "用学术标准"、"严格审一下" | 每个评价必须给证据强度分（1-5分），必须说明依据 |

## 四层锚点系统

每一条对话记录都带有四个维度的锚点，确保随时可以追溯：
1. 🕒 **时间锚点** — 什么时候讨论的
2. 📍 **内容锚点** — 对应 note.md 的精确行号范围
3. 🏷️ **主题锚点** — 讨论的是什么主题
4. 🔗 **回流锚点** — 这条讨论有没有被提炼到笔记里

## 状态管理

所有会话状态都落盘到隐藏的 `.session.yaml` 文件，内存不保留任何状态。
你随时可以说"先放着，明天继续"，下次自动恢复断点。

## 目录结构

```
~/reading-workspace/
├── articles/
│   └── {article-slug}/
│       ├── note.md           # 结构化笔记
│       ├── dialogue.md       # 完整对话记录 + 锚点索引
│       ├── progress.md       # 阅读断点（未读完时存在）
│       └── .session.yaml     # 隐藏的会话状态
├── cards/
│   ├── {card-id}.md          # 原子化卡片
│   ├── {card-id}.dialogue.md # 生成过程的对话记录
│   └── _index.md             # 全局卡片索引
└── review/
    └── {date}-review.md      # 复盘报告
```
