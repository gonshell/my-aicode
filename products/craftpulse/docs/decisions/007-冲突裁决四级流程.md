# ADR-007：冲突裁决四级流程

- **状态**：已接受（2026-08-01）
- **影响范围**：质量保障体系、多专家场景

## 背景

多专家意见不一致是知识库建设的必然场景：同一问题，老专家A说先查A参数，专家B说先查B参数，两个人都有经验依据。如果不裁决，知识库自相矛盾，用户无所适从。

## 候选方案

1. **少数服从多数**：按专家数量投票
2. **按专家权威**：职位高的说了算
3. **四级裁决流程**：先自动比对 → 再平行保留 → 专家仲裁 → 委员会终审
4. 全量人工仲裁：所有冲突都开会讨论

## 权衡

| 方案 | 优点 | 缺点 |
|:---|:---|:---|
| 多数投票 | 简单 | 多数不等于正确；工业现场少数专家可能才是对的 |
| 按权威 | 快 | 职位高≠技术对；压制不同意见 |
| 四级流程 | 系统、可追溯、留有缓冲 | 流程复杂，需配置裁决角色 |
| 全量人工 | 最准 | 成本极高，不可持续 |

## 决定

采用**四级裁决流程**：

1. **L1 自动比对**：录入时系统自动检测与现有知识的矛盾点，提示知识工程师
2. **L2 平行保留**：无法裁决的冲突，两条知识都保留，标注"存在分歧"，各自带专家来源和置信度，用使用数据定胜负
3. **L3 专家仲裁**：平行保留一段时间后，由该领域资深专家（非当事人）仲裁
4. **L4 委员会终审**：涉及安全、重大损失的冲突，升级到知识管理委员会终审，结果公示

## 理由

1. 工业现场"真理可能在少数人手里"，不能简单多数投票
2. 平行保留避免"强行合并"造成信息丢失，用实际使用数据做最终裁判
3. 分级流程控制成本：大部分冲突在L1-L2解决，只有极少数升级到L3-L4

## 后果

- 知识元数据需含"冲突状态"字段
- 消费端对存在分歧的知识展示"存疑"标记
- 需要配置仲裁专家和委员会角色（见治理篇）
