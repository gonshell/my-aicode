# 第四篇 生产端：知识工程工厂

> **本篇定位**：整个体系的"发动机"。90%的项目失败是因为这一层没做好。先把工厂建好，再生产产品。

## 第15章 知识工程工厂总体设计

### 15.1 工厂总览

```
┌─────────────────────────────────────────────────────────────┐
│                    知识工程工厂（生产端）                      │
│                                                              │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐   │
│  │  知识萃取工作台 │ → │  知识加工流水线 │ → │  知识质检车间  │   │
│  │  ① 访谈采集   │   │  ② 结构化编辑  │   │  ③ 质检机器人  │   │
│  └──────────────┘    └──────────────┘    └──────────────┘   │
│          ↓                    ↓                    ↓         │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  ④ 知识效果测试工作台（回归测试 | 用例库 | 错误归因）  │   │
│  └──────────────────────────────────────────────────────┘   │
│          ↓                                                    │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  ⑤ 知识运营总控台（健康度 | 贡献统计 | ROI | 告警）    │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 15.2 工厂的流水线逻辑

知识生产必须像工厂流水线一样，每个环节有明确的输入、处理、输出和质检点：

| 环节 | 输入 | 处理 | 输出 | 质检点 |
|:---|:---|:---|:---|:---|
| 采集 | 专家原始经验 | 引导式访谈+多模态采集 | 原始记录（录音+转写） | 完整性检查 |
| 结构化 | 原始记录 | 四维结构编辑 | 结构化知识草稿 | 字段校验 |
| 质检 | 结构化草稿 | 12项自动规则检查 | 合格知识条目 | 质量分≥75 |
| 测试 | 合格知识 | 回归测试+用例验证 | 验证报告 | 准确率≥90% |
| 发布 | 验证通过知识 | 专家审核确认 | 正式发布 | 审核签字 |

### 15.3 工厂的核心指标

| 指标 | 定义 | 目标值 |
|:---|:---|:---:|
| 知识生产速度 | 每周新增高质量知识数 | ≥5条/周 |
| 知识平均质量分 | 质检机器人打分均值 | ≥75分 |
| 生产到发布周期 | 采集到发布平均耗时 | ≤3个工作日 |
| 一次通过率 | 首次质检即合格的比例 | ≥70% |

## 第16章 专家访谈采集系统

### 16.1 不是简单录音

专家访谈采集系统不是录音软件，而是专门为知识萃取设计的采集工作台。它解决的是"如何让专家说出有价值的东西，并完整记录下来"。

### 16.2 核心模块

| 模块 | 功能 | 价值 |
|:---|:---|:---|
| 引导式访谈流程 | 按金字塔访谈法自动提示当前该问哪一层问题 | 新手也能按标准流程访谈 |
| 实时追问提示 | 语音识别+语义分析，实时提示"刚才那句话还没量化，请追问具体数值" | 不漏问关键信息 |
| 多模态采集 | 录音、拍照、屏幕录制、白板手写、现场视频 | 专家"比划着说"的内容也能记录 |
| 说话人自动分离 | 区分专家/访谈者/其他人 | 整理时无需再挑 |
| 术语自动识别 | 自动标记专业术语，关联术语库 | 减少理解偏差 |

### 16.3 引导式访谈流程（金字塔访谈法）

访谈不是聊天，必须按照四层结构逐层追问：

```
第一层：现象
  Q: 您第一次遇到这种情况是什么样子的？
  Q: 具体参数是多少？正常值是多少？异常值是多少？
  → 追问：这个现象还有别的表现吗？还有别的参数变化吗？

第二层：判断
  Q: 您是怎么判断出这个问题的？
  Q: 判断的时候先看哪个参数？为什么？
  → 追问：如果这个参数正常，您会怎么判断？

第三层：行动
  Q: 确认问题之后您是怎么处理的？
  Q: 步骤是什么？顺序重要吗？为什么？
  → 追问：有什么绝对不能做的吗？

第四层：边界
  Q: 这个方法在什么时候不适用？
  Q: 有没有看起来像这个情况，但其实不是的？
  → 追问：有没有犯过错误？当时怎么判断错的？
```

### 16.4 访谈记录的质量要求

- 访谈必须有录音，录音时长≥30分钟才有价值
- 访谈结束后24小时内完成初步转写和标注
- 每个访谈记录必须标注：访谈对象、时间、地点、主题

## 第17章 知识结构化编辑器

### 17.1 设计哲学：约束大于自由

知识结构化编辑器是知识工程师的"IDE"，核心设计原则是**约束大于自由**——没有空白文档，只有填表单。每个框该填什么、怎么填、格式如何，都有严格限制和实时校验。

> **反常识洞察**：越"难用"的编辑器，生成的知识质量越高。给用户10分自由，用户就给你10分混乱。

### 17.2 界面设计（四栏布局）

| 区域 | 内容 | 功能 |
|:---|:---|:---|
| 左栏 | 元数据面板 | 知识ID、标题、领域、设备、作者、置信度、版本、标签 |
| 中栏 | 四维结构编辑区 | 现象层（表单+参数表）、判断层（决策树拖拽）、行动层（步骤列表）、边界层（适用/不适用/反例） |
| 右栏 | 版本历史+来源信息 | 版本对比、来源录音播放、关联知识 |
| 底部 | 质量评分+自动保存状态 | 实时质量分、待改进项提示 |

### 17.3 核心交互设计

| 交互 | 说明 |
|:---|:---|
| 决策树拖拽编辑 | 判断层以可视化决策树呈现，节点可拖拽、双击编辑 |
| 实时质量评分 | 编辑过程中实时计算质量分，明确提示"还缺什么" |
| 自动保存 | 每次编辑自动保存草稿，支持版本对比 |
| 录音联动 | 选中某段知识可跳转到对应访谈录音时间点 |
| 字段级校验 | 必填项未填、格式不对、阈值冲突，实时红字提示 |

### 17.4 质量分算法（提交门槛）

| 检查项 | 权重 | 合格标准 |
|:---|:---:|:---|
| 四维完整性 | 30% | 四层全部填写 |
| 现象可观测性 | 15% | 参数有具体数值/阈值 |
| 判断可执行性 | 15% | 决策树分支完整、结论明确 |
| 行动可操作性 | 15% | 步骤具体、有安全注意事项 |
| 边界完备性 | 15% | 适用/不适用/反例齐全 |
| 元数据完整性 | 10% | 必填字段全部填写 |

**提交门槛**：质量分≥75分才允许提交审核。

## 第18章 智能质检机器人

### 18.1 定位：知识库的"单元测试框架"

就像代码提交前要跑单元测试，知识提交前必须过质检机器人。12项自动检查规则，从完整性和一致性到规范性和可测试性。

### 18.2 12项检查规则

| 类别 | 检查项 | 严重程度 |
|:---|:---|:---:|
| 完整性 | 四维结构是否完整 | 🔴 高（不通过不让提交） |
| 完整性 | 元数据必填项是否齐全 | 🔴 高 |
| 一致性 | 同设备同类知识阈值是否冲突 | 🔴 高 |
| 一致性 | 知识间是否存在矛盾结论 | 🔴 高 |
| 规范性 | 是否含模糊词汇（"大概""可能""差不多"） | 🟡 中 |
| 规范性 | 标题是否超过30字 | 🟡 中 |
| 规范性 | 格式是否符合规范（单位、术语） | 🟡 中 |
| 冗余性 | 是否与已有知识90%以上重复 | 🟡 中 |
| 可测试性 | 结论是否能用具体案例验证 | 🔴 高 |
| 时效性 | 引用的标准/规范是否过期 | 🔴 高 |
| 安全性 | 是否含危险操作未标注注意事项 | 🔴 高 |
| 可追溯性 | 是否有来源引用（录音/文档） | 🔴 高 |

### 18.3 运行模式

| 模式 | 触发时机 | 行为 |
|:---|:---|:---|
| 实时检查 | 提交时 | 不通过不让提交，逐项提示修改建议 |
| 定时全量扫描 | 每周日 | 生成《知识质量周报》 |
| 人工复核 | 高风险项 | 推送给知识管理员确认 |

## 第19章 知识效果测试工作台

### 19.1 定位：知识库的"集成测试框架"

这是整个生产端最核心、也最容易被遗漏的系统。没有回归测试的"优化"都是耍流氓。

### 19.2 标准测试用例库

每个场景至少50个测试问答对：

| 用例类型 | 示例 | 用途 |
|:---|:---|:---|
| 正面案例 | "振动65μm，油温45℃，怎么处理？" | 验证正常回答 |
| 边界案例 | "振动正好60μm，怎么处理？" | 验证边界判断 |
| 反例 | "振动正常，但有异音，怎么处理？" | 验证排除逻辑 |
| 极端案例 | "冬季满负荷，振动62μm，怎么处理？" | 验证组合条件 |

### 19.3 批量回归测试

- 知识库每更新一次，自动跑全部测试用例
- 输出报告：v1.2 → v1.3，准确率从78%提升到85%，召回率从82%降到79%
- **准确率不升反降的版本禁止发布**

### 19.4 错误归因分析

| 错误类型 | 归因 | 处理 |
|:---|:---|:---|
| 回答错误 | 知识缺失 | 补充知识 |
| 回答错误 | 检索不准 | 优化检索策略 |
| 回答错误 | 推理错误 | 优化决策树 |
| 回答错误 | 知识本身错误 | 修正知识，走版本更新 |

### 19.5 对比测试

- 知识库回答 vs 专家本人回答，一致率
- 不同专家的回答，一致率
- 一致性低的场景，标记为"待讨论知识"

## 第20章 知识运营总控台

### 20.1 定位：知识库的"运维监控面板"

就像运维看系统健康度，知识运营看知识库健康度。只看5个核心指标，多了都是噪音。

### 20.2 五大核心指标

| 指标 | 定义 | 警戒值 |
|:---|:---|:---|
| 📈 知识生产速度 | 每周新增高质量知识数 | <5条/周 告警 |
| ✅ 知识平均质量分 | 质检机器人打分均值 | <70分 告警 |
| 📉 专家咨询下降率 | 与基线相比专家被咨询次数减少比例 | <20% 说明没用好 |
| ⚠️ 负反馈率 | 用户点"回答不准确"的比例 | >10% 告警 |
| 🔄 知识新鲜度 | 超过1年未复审知识占比 | >15% 告警 |

### 20.3 仪表盘展示

- 实时监控五大指标
- 专家贡献排名（谁贡献了多少高质量知识）
- 知识库整体健康度评分（0-100）
- 按领域/设备/专家维度下钻分析

## 第21章 大模型辅助萃取工具集

### 21.1 定位

大模型不是替代知识工程师，而是放大知识工程师的效率。每个环节都有对应的LLM辅助能力，但**所有输出都必须经过人工审核确认**。

### 21.2 工具集

| 环节 | LLM辅助能力 | 人工审核点 |
|:---|:---|:---|
| 访谈后 | 录音自动转写+说话人分离+重点标注 | 转写准确性 |
| 结构化 | 自动生成四维结构初稿 | 边界条件、反例是否完整 |
| 质检 | 自动检测模糊词汇、逻辑漏洞 | 高风险项人工确认 |
| 测试 | 自动生成测试用例 | 用例覆盖度 |
| 运营 | 自动生成周报摘要 | 数据准确性 |

### 21.3 使用铁律

> **LLM输出的知识条目，未经专家审核确认，不得进入正式知识库。**
> **LLM输出的所有内容，必须标注"AI辅助生成，未经审核"字样。**
