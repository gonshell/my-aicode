# 第八篇 风险与失败模式

> **本篇定位**：提前把所有可能的坑列出来，每个坑都有成熟的缓释方案。历史总是惊人的相似——1980年代第一代专家系统最终衰落，不是死在技术上，而是死在三个非技术问题上：知识获取太慢太贵、知识很快过时没人更新、用户不信也不敢用。

## 第39章 十大已知风险与缓释措施

### 39.1 风险清单总览

| 风险 | 等级 | 来源 | 核心缓释 |
|:---|:---:|:---|:---|
| R1 专家不配合 | 🔴 P0 | 时间机会成本高 | 反向减负机制（第30章） |
| R2 知识质量差 | 🔴 P0 | 自由文本无约束 | 结构化表单+质检机器人（第17-18章） |
| R3 用户不信不敢用 | 🔴 P0 | 无推理链无责任边界 | 可解释性+置信度分级（第23、25章） |

| R6 知识工程师能力不足 | 🟠 P1 | 岗位被低估 | 五级能力体系（第29章） |

### 39.2 三个致命风险的详细分析

#### R1：专家不配合（最致命）

**表现**：专家觉得"知识萃取是在浪费时间"，访谈敷衍、推脱、拒绝。

**根本原因**：专家的时间机会成本极高（1小时访谈=少处理3个现场问题），单纯的物质激励（积分、奖金）与机会成本相比不值一提。

**缓释**：
- 知识萃取师驻场减负（帮专家干活，专家"顺便"分享）
- 先做"种子专家"，用成功案例带动其他人
- 领导明确表态支持，但不用行政命令强压

#### R3：用户不信不敢用（第二致命）

**表现**：系统建好了，但一线员工遇到问题还是直接打电话找专家。

**根本原因**：用户不确定系统答案是否正确，出了事谁负责说不清楚。

**缓释**：
- 每条回答展示完整推理链和来源
- 置信度分级，低置信度明确转人工
- 从"辅助参考"场景切入（先让用户把系统当"第二专家"），逐步建立信任
- 用真实案例宣传"系统帮某班组避免了事故"

#### R4：知识过时无人更新（第三致命）

**表现**：知识库建了500条，但一年后一半已经过时，没人更新，用户逐渐发现答案不准，系统被弃用。

**根本原因**：没有保鲜机制，知识生产是一次性的。

**缓释**：
- 自动衰减机制：过时知识自动降级，倒逼更新
- 使用即保鲜：知识被验证使用，新鲜度重置
- 复审任务自动派发给知识作者

## 第40章 典型失败模式预警

### 40.1 十大失败模式

| 失败模式 | 典型症状 | 预防 |
|:---|:---|:---|
| 运动式推进 | 3个月突击500条，第4个月就停了 | 慢启动、机制化 |
| 重前端轻生产 | 界面精美但知识只有100条 | 先生产端后消费端 |
| 知识萃取当行政任务 | 部门随便派个人"兼职做" | 专职团队+能力体系 |
| 回避责任问题 | "系统只是参考"但出了事没人管 | 明确审计和责任链 |
| 只记录正面知识 | 没有错误教训库 | 负面知识库强制 |
| 追求知识数量 | 500条灌水知识，检索全是噪音 | 质量分门槛 |
| 专家走形式 | 访谈30分钟结束，全是"应该"没有"边界" | 四层追问法+录音要求 |
| 系统脱离工作流 | 用户还得专门打开一个系统问问题 | 嵌入IM/工单/移动端 |
| 一把手依赖 | 领导调走项目就停 | 制度化+多部门 |
| 不做ROI评估 | 钱花了一年说不清值不值 | 分阶段ROI测算 |

### 40.2 失败模式与历史教训的对应

> **40年的轮回**：1980年代专家系统失败的三大原因——知识获取瓶颈、知识维护瓶颈、信任瓶颈——在本方案的失败模式表中依然占据前列。大模型解决了部分技术问题，但这三个根本问题必须靠机制设计解决。

## 第41章 早期预警指标

### 41.1 三级预警体系

| 级别 | 含义 | 触发条件 | 应对 |
|:---:|:---|:---|:---|
| 🔴 红灯 | 项目濒临失败 | 连续2月生产速度<5条/周 或 负反馈率>15% 或 专家访谈完成率<50% | 紧急复盘，调整策略 |
| 🟡 黄灯 | 出现明显问题 | 生产速度<5条/周 或 质量分<70 或 用户月活下降>20% | 专项整改 |
| 🟢 绿灯 | 健康运行 | 各项指标达标 | 持续运营 |

### 41.2 关键预警指标

| 指标 | 监测频率 | 红灯阈值 | 黄灯阈值 |
|:---|:---:|:---:|:---:|
| 知识生产速度 | 每周 | <5条/周（连续2月） | <5条/周 |
| 知识平均质量分 | 每周 | <70分 | <75分 |
| 负反馈率 | 每周 | >15% | >10% |
| 专家访谈完成率 | 每月 | <50% | <70% |
| 用户月活跃数 | 每月 | 下降>40% | 下降>20% |
| 知识新鲜度分布 | 每月 | 过期知识>30% | 过期知识>15% |
| ROI达成度 | 每季度 | <50% | <80% |

### 41.3 预警处理机制

- 预警自动推送给CKO和知识管理委员会
- 红灯必须召开专题复盘会（1周内）
- 预警处理结果写入运营周报，跟踪闭环

## 第42章 应急回滚方案

### 42.1 应急场景

| 场景 | 严重性 | 响应时效 |
|:---|:---:|:---:|
| 系统给出的建议导致事故 | 🔴 致命 | 立即响应 |
| 负面知识被"验证为错误" | 🔴 致命 | 24h内 |
| 知识库被错误批量更新 | 🟠 严重 | 4h内 |
| 专家集体抵制萃取 | 🟠 严重 | 1周内 |
| 数据泄露 | 🔴 致命 | 立即响应 |

### 42.2 应急响应流程

```
【步骤1】识别事件，立即暂停相关知识推荐
【步骤2】隔离：标记涉事知识，停止推荐（不下架，保留证据）
【步骤3】定位：回溯是哪次更新引入的问题（版本对比）
【步骤4】回滚：恢复到上一个验证通过的版本
【步骤5】分析：根因分析，写入事故报告
【步骤6】改进：更新测试用例，防止同类问题再发
【步骤7】恢复：修正后重新走发布门禁流程
```

### 42.3 回滚保障

- 知识库版本必须可回滚（每日自动备份）
- 每次发布自动生成"回滚点"
- 应急演练每季度一次（模拟知识库错误更新演练）

## 第43章 数据安全与保密（补充）

### 43.1 知识分级

| 级别 | 定义 | 示例 | 权限 |
|:---|:---|:---|:---|
| 公开级 | 通用操作知识 | 标准操作流程 | 全员可查 |
| 内部级 | 内部工艺知识 | 设备维护策略 | 相关岗位可查 |
| 机密级 | 核心工艺知识 | 核心配方、工艺参数 | 授权专家+审批 |
| 绝密级 | 商业机密 | 未公开技术方案 | 极少数授权 |

### 43.2 数据安全要求

- 所有知识访问留痕（谁、何时、看了什么）
- 权限按岗位最小化授予
- 专家访谈录音加密存储，严格授权
- 测试数据脱敏，禁止使用真实设备数据
- 供应商（LLM服务）需签署保密协议，敏感数据不得出域

### 43.3 合规注意

- 涉及安全生产的知识必须符合国家/行业标准
- 系统给出的安全类建议需标注"依据XX标准/规程"
- 数据跨境传输需符合《数据安全法》《个人信息保护法》
