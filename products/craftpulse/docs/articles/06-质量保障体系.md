# 第七篇 质量保障体系

> **本篇定位**：知识库的"免疫系统"——保证知识质量不下降，不出现错误答案害人。

## 第34章 知识质量保障总体框架

### 34.1 三道防线

```
┌────────────────────────────────────────────────────────────┐
│                    三道防线（全流程质量保障）                 │
│                                                            │
│  第一道防线（提交时）        第二道防线（发布前）    第三道防线（使用中）│
│  质检机器人12项检查         测试工作台回归测试     用户反馈闭环       │
│  · 完整性/一致性            · 50+测试用例          · 准确/不准确    │
│  · 规范性/冗余性            · 批量回归             · 不完整反馈     │
│  · 可测试性/时效性           · 对比测试             · 负反馈自动处理  │
│  · 安全性/可追溯性           · 准确率≥90%才发布     · 置信度动态调整  │
│                                                            │
│  质量分≥75才允许提交         准确率不升反降禁止发布  负反馈率>10%告警  │
└────────────────────────────────────────────────────────────┘
```

### 34.2 质量定义

知识质量 = 准确性 × 完整性 × 时效性 × 可操作性 × 可追溯性

| 维度 | 定义 | 度量方式 |
|:---|:---|:---|
| 准确性 | 知识结论与事实一致 | 测试用例通过率 |
| 完整性 | 四维结构完整、无遗漏 | 质检机器人完整性检查 |
| 时效性 | 知识未过时、未过期 | 复审周期、新鲜度指标 |
| 可操作性 | 用户能按知识执行 | 步骤具体性检查 |
| 可追溯性 | 结论可溯源到原始来源 | 来源引用完整性 |

## 第35章 知识冲突裁决流程

### 35.1 冲突的来源

- 不同专家对同一问题有不同判断
- 新旧知识阈值不一致
- 不同设备/环境下的知识看似矛盾
- 负面知识与正面知识边界重叠

### 35.2 冲突裁决四级流程

```
第一级：自动识别
  质检机器人发现同领域知识结论矛盾 → 标记"冲突"状态

第二级：加权比较
  对比双方知识：专家历史准确率权重 × 置信度
  · 明显一方占优 → 采纳占优方，另一方标记"备选"
  · 旗鼓相当 → 升级第三级

第三级：专家仲裁
  推送给中立资深专家（非冲突双方）仲裁
  · 仲裁结论 → 更新知识，记录仲裁意见
  · 无法裁决 → 升级第四级

第四级：平行保留 + 事后追溯
  两条知识平行保留，回答时并列展示差异
  · 实际使用数据持续验证 → 3个月后以验证结果定胜负
  · 责任人：知识管理委员会
```

### 35.3 冲突处理原则

- 不轻易删除任何一方的知识（保留证据链）
- 冲突本身就是重要的知识（说明存在未覆盖的边界条件）
- 平行保留期间，回答必须展示"存在不同观点"

## 第36章 知识自动衰减机制

### 36.1 为什么需要衰减

工业场景知识具有强时效性：
- 设备改造后旧知识失效
- 工艺变更后标准更新
- 专家认知随实践演化

**不衰减的后果**：知识库充满"可能已过时"的知识，用户逐渐不信任整个系统。

### 36.2 知识半衰期算法

```
知识新鲜度 = 初始新鲜度(1.0) × 衰减系数^月数

衰减系数按知识类型区分：
· 设备操作类知识：0.97/月（12个月后新鲜度约0.69）
· 诊断决策类知识：0.98/月（12个月后新鲜度约0.78）
· 制度标准类知识：0.95/月（12个月后新鲜度约0.54）
· 历史案例类知识：0.99/月（基本不衰减）
```

### 36.3 衰减触发的动作

| 新鲜度区间 | 状态 | 系统行为 |
|:---:|:---|:---|
| 0.8-1.0 | 新鲜 | 正常推荐 |
| 0.6-0.8 | 趋旧 | 推荐时提示"建议核实" |
| 0.4-0.6 | 过时预警 | 自动生成复审任务，通知作者 |
| <0.4 | 过期 | 停止主动推荐，仅检索时显示"已过期" |

### 36.4 保鲜机制

- 使用即保鲜：知识被验证使用一次，新鲜度重置+0.1
- 复审即保鲜：专家复审通过，新鲜度重置为1.0
- 更新即保鲜：知识版本更新，新鲜度重置为1.0
- 无人使用 + 无人复审 → 自动进入"淘汰观察区"，90天后归档

## 第37章 回归测试体系

### 37.1 回归测试铁律

> **每次知识库更新，必须跑完整测试用例集。准确率不升反降的版本禁止发布。**

### 37.2 测试用例库管理

| 用例类型 | 数量占比 | 来源 |
|:---|:---:|:---|
| 正面案例 | 50% | 专家访谈提炼、历史工单 |
| 边界案例 | 20% | 阈值边界、条件组合 |
| 反例 | 15% | 负面知识库提炼 |
| 极端案例 | 15% | 专家经验、事故复盘 |

### 37.3 版本发布门禁

```
发布流程：
1. 知识库变更 → 生成候选版本 v1.3
2. 全量回归测试 → 输出准确率/召回率
3. 对比 v1.2 基线：
   · 准确率 ≥ v1.2 且 ≥90% → 通过，发布
   · 准确率 < v1.2 → 阻塞，回滚变更
   · 准确率持平但召回率显著提升 → 可发布
4. 发布后 24h 内观察线上负反馈率
```

### 37.4 测试环境要求

- 测试环境与生产环境完全隔离
- 测试数据脱敏（真实设备数据不可入测试库）
- 测试过程自动记录，可复现

## 第38章 持续优化闭环

### 38.1 完整闭环

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ 用户反馈  │ → │ 问题定位  │ → │ 知识修正  │ → │ 回归测试  │
└─────────┘    └─────────┘    └─────────┘    └─────────┘
      ↑                                           │
      │                                           ↓
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ 效果验证  │ ← │ 数据监控  │ ← │ 重新发布  │ ← │ 审核确认  │
└─────────┘    └─────────┘    └─────────┘    └─────────┘
```

### 38.2 优化优先级

| 优先级 | 触发条件 | 动作 |
|:---:|:---|:---|
| P0 | 负面知识被"验证为错误"或安全类知识出错 | 立即下架，24h内修正 |
| P1 | 负反馈率>10%的知识条目 | 7天内完成修正 |
| P2 | 多次被用户问但无命中的主题 | 生成萃取任务 |
| P3 | 长期未使用的知识 | 复审或归档 |

### 38.3 持续优化的关键

- 优化不是"发现问题再修"，而是**机制化**：每次反馈都自动进入处理管道
- 知识库质量是"用出来"的：使用越多、反馈越多、修正越多、越准确
- 运营周报必须包含：新增知识、修正知识、负反馈趋势、新鲜度分布
