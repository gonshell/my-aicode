### 22.3 设计原则

- 一个答案，多渠道触达：同一知识库支撑所有前端

- 全程审计：所有问答记录留痕

## 第23章 智能问答引擎

### 23.1 混合引擎架构

纯语义检索（RAG）回答工业问题是危险的——知识库回答必须经过规则校验。采用"语义检索 + 规则推理 + 决策树执行"三层混合：

| 层 | 技术 | 作用 |
|:---|:---|:---|
| 第一层：语义检索 | 向量检索+关键词检索混合 | 召回候选知识条目 |
| 第二层：规则校验 | 知识四维结构校验 | 过滤不适用知识（边界层检查） |
| 第三层：决策树执行 | 结构化决策树推理 | 按判断层执行，输出结论+推理链 |

### 23.2 回答格式（可解释性约束）

每条回答必须包含：

```
【回答】振动异常建议按以下步骤处理...

【推理链】
1. 依据知识 KB-2025-0042（作者：张建国，置信度0.85）
2. 现象匹配：X方向振动 62μm > 60μm 阈值
3. 边界检查：当前负荷75%，在适用范围内
4. 决策执行：按决策树 → 建议降负荷并检查频谱

【来源】原始访谈录音 REC-2025-0108，时间戳 12:34
【免责声明】本回答仅供参考，最终决策权在操作人员
```

### 23.3 回答质量保障

- 无知识命中 → 明确说"知识库中暂无此问题的可靠答案"，转人工
- 多知识冲突 → 并列展示并说明差异，不擅自取一个
- 边界不符 → 提示"该知识不适用于当前条件"
- 低置信度 → 标注置信度并建议人工复核

## 第24章 场景化智能体

### 24.1 为什么需要场景化智能体

通用问答无法满足工业场景的专业需求。按场景构建垂直智能体，每个智能体内置该场景的专业流程、知识范围和交互范式。

### 24.2 典型场景智能体

| 智能体 | 场景 | 核心能力 |
|:---|:---|:---|
| 故障诊断智能体 | 设备异常诊断 | 引导式排查、决策树执行、频谱分析建议 |
| 操作指导智能体 | 标准操作执行 | 步骤引导、安全提醒、防错校验 |
| 风险预警智能体 | 安全隐患识别 | 异常参数监控、风险等级评估 |
| 检修方案智能体 | 停机检修准备 | 检修步骤、备件清单、历史案例 |
| 事故复盘智能体 | 事故原因分析 | 负面知识库检索、教训提取 |

### 24.3 智能体编排

每个场景智能体由三部分组成：
- **知识范围**：绑定该场景的知识子集（领域+设备+标签过滤）
- **流程编排**：引导式对话流程（如诊断路径、操作步骤）
- **工具调用**：检索、决策树执行、案例匹配、专家转接

## 第25章 人机协同责任边界机制

### 25.1 原则

**最终决策权永远在人。** 系统是决策支持工具，不是决策主体。这是法律、伦理和信任的底线。

### 25.2 置信度三档响应

| 置信度 | 系统行为 | 界面呈现 |
|:---:|:---|:---|
| ≥0.85 | 给出明确建议 | 绿色边框，明确步骤 |
| 0.70-0.84 | 给出选项和风险 | 黄色边框，"建议人工复核" |
| <0.70 | 不给建议，转人工 | 红色边框，"请联系专家XXX" |

### 25.3 审计日志

每次问答必须记录：
- 用户、时间、场景、问题原文
- 系统回答、引用知识、置信度
- 用户是否采纳、实际结果
- 出现事故时，可完整追溯：系统给了什么建议 → 人做了什么决策 → 为什么

### 25.4 免责与担责设计

- 系统所有回答自带"仅供参考"标识
- 用户采纳系统建议造成损失：可追溯系统建议是否合规（知识是否有边界检查）
- 用户未采纳系统建议造成损失：记录用户决策，明确责任在操作方

## 第26章 多端接入适配

### 26.1 IM机器人（飞书/企业微信）

- 自然语言提问，返回卡片式回答
- 支持@机器人提问、群内问答
- 高频问题自动聚合统计

### 26.2 移动端APP

- 关键知识本地缓存，离线可用
- 拍照提问：拍故障现象，自动匹配知识
- 语音提问：边说边查

### 26.3 工单系统插件

- 工单创建时自动推荐相关知识和历史案例
- 工单处理中可引用知识条目
- 工单关闭时沉淀"本次问题是否验证了某条知识"

### 26.4 AR眼镜现场指引

- 现场检修时叠加显示操作步骤
- 视频通话远程专家支持
- 适用于复杂装配、危险作业场景

## 第27章 用户反馈闭环

### 27.1 反馈入口

每个回答下方必须有三个按钮：
- ✅ 准确
- ❌ 不准确
- ⚠️ 不完整

### 27.2 反馈处理流程

```
用户反馈 → 自动记录 → 分类处理
  ├─ 不准确 → 质检机器人复核 → 通知知识作者 → 修正 → 回归测试 → 重新发布
  ├─ 不完整 → 标记待补充 → 生成萃取任务 → 专家补充 → 审核 → 发布
  └─ 准确 → 知识置信度+0.02，验证记录+1
```

### 27.3 反馈闭环的核心价值

- 反馈是知识置信度动态调整的重要数据源
- 反馈是发现知识空白区的关键信号
- 反馈闭环让知识库"越用越准"
